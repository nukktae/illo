# P02 직무 찾기 Spec

버전 v0.4 (2026.11.02) | 담당: 이상혁 | PRD: [P02-job-search.md](../prd/P02-job-search.md) | 공통: [00-common.md](00-common.md)

상태: PR #6 리뷰 반영 개정안 팀 확인 완료·이번 Spec 작성 완료·코드 변경 계획 승인·리뷰 반영 구현·로컬 검증 완료. 다음은 이전 구현 이력이다. 사용자 보고로 P02 v1.3 정정 팀 리뷰 완료 확인. 승인된 프로토타입 범위로 Spec에 따른 프로토타입 구현·로컬 검증 완료, 실제 연동·PR 검증 대기. 실제 P05 저장·역량 분석 연동은 제외한다.

## 1. 기술 스택과 구현 범위

기존 Python 생성기, 정적 HTML 및 `dc-lite.js`를 유지한다. 공통 Spec의 빌드·디자인·검증 원칙을 따른다. 새 서버·DB·AI·외부 라이브러리를 도입하지 않는다.

| 기능 ID | 화면·데이터·상태·API 범위 |
|---|---|
| P02-F01 | 기존 7개 직무 선택·검색. 모바일도 같은 선택 상태·제목을 사용하도록 일치시킴. 신규 API 없음 |
| P02-F02 | 기존 신입/인턴·경력 전환 유지. 실제 경력 공고 신규 구현 제외 |
| P02-F03 | SNS 일반 역량 목록 유지. 고정 페르소나의 체크를 사용자 분석처럼 표시하지 않고 미등록 안내. 다른 직무 상단 분석은 준비 중 유지 |
| P02-F04 | 회사·제목 검색 유지, 검색 후 정렬·페이지 일관성 회귀 검증 |
| P02-F05 | 고유 역량 수 내림차순·동점 최신순·미등록 최신순 대체·미분석 후순위 |
| P02-F06 | 10개 페이지와 기존 링크·저장 유지, 상태별 역량 박스와 조건 변경 시 페이지 초기화 |
| P02-F07 | SNS 트렌드 팝업 유지, 다른 직무에 SNS 팝업을 노출하지 않음 |
| P02-F08 | 미등록·분석 완료0개 이상·미분석 구분 및 안내 |

개정 구현의 중심은 F05 → F08 → F06이다. F01·F03의 수정은 승인된 모바일 일관성과 미등록 안내를 위해 필요한 범위다. P05 화면이나 저장 계약을 임의로 변경하지 않는다.

## 2. 화면과 컴포넌트

원본은 `design/screens/20_job_search.py`. 생성 대상은 `S1-list.dc.html`, `m-S1-list.dc.html`과 대응하는 `prototype/*.html`이다.

| 컴포넌트 | 정상·빈 상태·오류·로딩 처리 |
|---|---|
| 직무 선택 | 같은 jobs 상태로 7개 직무 칩·검색 표시. 모바일 가로 넘침은 칩 영역의 기존 스크롤 방식으로 수용, 제목은 선택 직무에 맞춤 |
| 상단 역량 카드 | P02 전용 렌더 함수에서 기존 RANK 일반 정보를 재사용. 미등록 시 사용자 체크와 체크했다는 문구 없이 “이력서를 등록해주세요”. 다른 직무 분석 준비 중 표시 |

| 공고 역량 칩 | 미등록: #F2F4F6 배경/#4E5968 글자, 반경6px, 12px, padding 3px 8px. “이력서를 등록해주세요”. 클릭 동작 없음 |
| 분석 완료 칩 | 기존 파란 강조, “내 경험과 겹치는 역량 N”. N=0도 표시 |
| 미분석 칩 | 회색, “역량 분석 준비 중”. 숫자 없음 |
| 목록·페이지 | 검색 결과 없음은 기존 문구와 지우기. 필터→정렬→페이지 분할. 한 페이지10개 |
| 로딩·분석 오류 | 현재 비동기 호출 없음. 결과를 확인할 수 없으면 미분석이며 성공0개로 변환하지 않음. 실제 로딩·실패 API UX는 후속 연동 의존성 |

공통 `fit_card()`를 고치지 않고 P02 전용 상태 표시를 작성해 홈 등 다른 페이지에 영향을 주지 않는다. 공통 파일 변경이 필요해지면 구현 범위를 재확인하고 프로젝트의 사전 공유 규칙을 따른다.

## 3. 데이터 모델

새 DB 없음. 기존 공고 메타데이터(id/company/title/type/deadline/url/created)는 유지한다. 원본 JSON을 임의 개인화 결과로 덮어쓰지 않는다.

### 프로토타입 입력 계약

- `resumeContent`: 현재 표시하는 이력서의 작성된 값 목록. 비어 있지 않은 문자열이 하나라도 있으면 내용 있음이다. placeholder/안내/추천 항목은 이 배열에 넣지 않는다. 현재 사전 작성된 이력서에는 내용이 있으므로 기본 상태는 내용 있음이다. 저장 서버 유무나 저장 버튼 클릭으로 판정하지 않는다.
- `resumeSkillIds`: 문자열 ID 배열 또는 null. 등록 상태와 역량 데이터의 준비 여부를 구분한다.
- `postingSkillIds`: 공고별 문자열 ID 배열 또는 null. null/누락은 미분석, 유효한 빈 배열은 분석 완료·역량0개다.
- SNS의 기존 `ov` 배열은 현재 사전 이력서에 대한 기존 겹치는 역량 목록이다. 이를 `presetOverlapSkillIds`로 보존하고 동일 사전 이력서 `seedId`일 때만 재사용한다. 공고 전체 요구 역량으로 가장하지 않으며 다른 사용자/다른 직무로 전용하지 않는다.
- 이력서 내용이 있고 양쪽 역량 배열이 유효할 때만 `Set`으로 중복 제거 후 교집합 크기를 구한다. 잘못된 타입·빈 ID가 섞인 입력은 분석 불가로 처리한다. ID는 사전 정규화된 값으로 보고 임의 동의어 추정은 하지 않는다.
- 테스트 자료는 가상 공고 ID와 가상 역량 ID로 별도 생성한다. 제품에는 테스트용 상태 스위치·쿼리 파라미터·localStorage 우회 값을 추가하지 않는다.

### 날짜 기준

현재 `cr`/`created`는 숫자형 밀리초 타임스탬프다. 유한한 양수만 등록일로 인정하고 0·누락·잘못된 값은 날짜 없음으로 취급한다. 다른 직무의 기존 `cr=0`에서 실제 날짜를 지어내지 않는다. 날짜가 없으면 정렬 전 원본 순서를 유지한다.

## 4. API와 외부 의존성

신규 API·키·네트워크 요청 없음. 실제 이력서 연동은 후속 작업이다. 사용자 저장 데이터가 생겼을 때 어떤 계약으로 P02에 전달할지 P05 담당자와 합의해야 한다.

실제 서비스에서는 이력서 등록 여부, 정규화된 역량 ID, 공고별 요구 역량 및 원문 근거·분석 상태가 필요하다. 현재 이 계약은 프로토타입의 테스트 입력 계약이며 팀 공통 DB/API 확정안이 아니다.

## 5. 상태와 정렬 흐름

1. 직무 유효성 확인. 없는 키는 기존 SNS 기본값으로 처리한다.
2. 원본 순서 인덱스를 보관하고 검색·고용형태 필터를 적용한다.
3. 각 공고 상태를 `unregistered`, `analyzed(count)`, `pending`으로 계산한다.
4. 추천순:
   - 미등록: 최신순 → 원본 인덱스.
   - 등록: 분석 완료 우선 → 고유 교집합 수 내림차순 → 최신순 → 원본 인덱스. 미분석끼리는 최신순 → 원본 인덱스.
   - 추천순에서만 시연 공고를 최우선으로 둔다. 최신순·마감 임박순은 시연 여부를 정렬 키에 넣지 않는다. 직무·검색·필터 적용 후에만 고정하며 일반 공고 및 복수 시연 공고 내부는 각 정렬 기준을 따른다.
5. 최신순과 마감 임박순은 선택한 기준을 따른다. 추천순 안내는 해당 정렬에만 표시한다.
6. 전체 정렬 결과를 10개씩 분할한다. 직무·검색·필터·정렬 변경 시 page=1. 빈 결과는 pages=1, 목록0개이며 기존 빈 상태 표시.
7. 기존 비교하기·원문·저장·트렌드 동작을 유지한다.

역량 계산과 정렬은 UI와 분리된 순수 함수로 작성해 같은 로직을 7개 직무와 테스트 자료에 사용한다. 공고 입력 배열을 제자리 정렬하지 않는다.

## 6. AI 사용

이번 범위에 신규 AI 호출은 없다. 모델·프롬프트·JSON 응답·시간 제한을 확정하거나 실제 분석된 것으로 표시하지 않는다. 실제 역량 추출·정규화·원문 검증·실패/갱신 정책은 PRD의 미결 사항으로 유지한다.

## 7. 오류·예외 처리

| 상황 | 처리 | 검증 |
|---|---|---|
| 이력서 내용 없음 | 미등록 안내, 추천순에서 최신순 대체 | 빈 이력서 테스트 자료 |
| 등록됐으나 역량 입력 누락/잘못된 타입 | 미분석 안내, 숫자0 생성 금지 | 별도 자료 |

| 날짜 없음/동점 | 같은 역량 그룹 내 날짜 있는 항목 뒤, 이후 원본 순서 | 별도 자료 |
| 결과 없음 | 기존 검색 결과 없음·지우기 | 브라우저 |
| 긴 회사명·안내 | 줄바꿈/기존 제목 처리 유지, 칩 잘림·버튼 겹침 없음 | 320px |

오류 수집 서버는 추가하지 않는다. 테스트 결과는 수정 기록에 남기고 실제 사용자 개인정보는 테스트 자료에 포함하지 않는다.

## 13. 이력서 내용 유무 기준 정정 (2026.11.02)

사용자가 정정안 팀 리뷰 완료 및 구현을 승인했다. v0.2의 기본 미등록 가정을 철회한다. `hasResumeContent(profile)`로 작성된 값의 존재를 확인하며 사전 이력서의 활동 문장은 기존 `EXP_LINES`를 재사용한다. SNS 원본 ov는 사전 이력서 ID가 맞을 때만 재사용하고 다른 직무는 미분석으로 유지한다. 이력서가 비어 있으면 사전 역량 목록이 남아 있어도 등록 안내가 우선한다.
