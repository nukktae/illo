# 공통 Spec — 기존 프로토타입 수정

버전 v0.1 (2026.11.02) | 범위: P03-F13·P03-F14·P03-F15 | 상태: 사용자 승인 범위로 작성, 구현 계획 승인·프로토타입 로컬 검증 완료 (실제 서비스·PR 검증 별도)

## 1. 적용 범위와 기술 스택

현재 Python 3 화면 생성기, 정적 HTML, `design/scripts/dc-lite.js` 상태 렌더러를 유지한다. 실제 서비스 기술 스택을 팀 전체의 확정안으로 선언하는 문서가 아니다. 신규 서버·DB·AI 호출·이력서 저장을 추가하지 않는다.

## 2. 구조와 변경 규칙

- 화면 원본은 `design/screens/`, 데이터는 `design/data/`다. 페이지 담당 파일에서 기능 ID별로 수정한다.
- `sh design/build.sh`로 `design/canvas/`와 `prototype/`를 재생성한다. 생성물을 손으로 수정하지 않는다.
- 공통 `design/screens/01_base.py` 변경 전 단톡 공유가 필요하다 (`CONTRIBUTING.md`). 기존 호출의 기본 동작을 보존하고 영향받는 홈·목록도 검증한다.
- 사용자 지정 작업 브랜치 Lsh를 유지한다. 커밋·push·PR·배포는 별도 요청과 프로젝트 리뷰 절차를 따른다.

## 3. 데이터·API·보안

이번 변경에는 DB 표, API 입력·출력·오류 형식 변경이 없다. 고정 예시 데이터와 실제 사용자 저장 데이터는 구분한다. 새 API 키가 필요하지 않으며 키·실제 개인정보를 테스트 자료에 넣지 않는다. 상태 변경은 현재 렌더러의 `setState`를 사용한다.

## 4. 디자인

Pretendard, 배경 `#FAFAFA`, 흰 카드, 반경 20px, 그림자 없음. 주요 행동은 `#3182F6`, AI 배지는 기존 보라색을 유지한다. P03 버튼·여백의 구체적인 수치는 [P03 Spec](P03-compare.md)을 따른다. 데스크톱과 모바일 생성 화면을 각각 확인한다.

## 5. 검증과 완료 기준

- Python 표준 라이브러리 기반 생성 구조·빈 데이터 테스트와 실제 Chromium 클릭·레이아웃 검증을 사용한다. 신규 앱 프레임워크는 도입하지 않는다.
- 기본 검증: 빌드 성공, 문서 링크·기능/테스트 ID 대응, 변경 diff의 공백 오류 및 의도하지 않은 생성물 변경 확인.
- 브라우저에서 데스크톱 1440px, 모바일 390px와 좁은 320px를 확인한다. 버튼 크기·카드 간격·가로 넘침을 측정하고 화면 캡처를 남긴다.
- 테스트 결과는 통과·실패·의존성 미구현으로 실행 불가를 구분한다. 미실행 항목을 통과로 계산하지 않는다.
- 로컬 검증 완료와 PR 미리보기·팀 리뷰 완료는 별도 상태다. 변경 내역과 제한은 `docs/CHANGELOG.md`에 남긴다.

## 6. 실제 서비스 미결 사항

다음은 기존 가이드의 제안을 바탕으로 한 선택지이며 이번 변경에서 결정하거나 구현하지 않는다.

| 항목 | 선택지 | 제안 및 상태 |
|---|---|---|
| 서비스 UI | Next.js App Router / 별도 SPA | 가이드 제안 Next.js 우선 검토, 팀 결정 대기 |
| 저장·인증 | Supabase / 별도 서버와 DB | 가이드 제안 Supabase 우선 검토, 스키마·소유자 미결 |
| AI | Claude API / 다른 구조화 출력 지원 API | 가이드 제안 Claude 우선 검토, 모델·비용·검증 미결 |
| API 계약·테스트 도구 | 프레임워크 내부 API / 별도 서버 API | 서비스 구조 확정 후 응답·오류 스키마와 테스트 도구 결정 |

## 7. 변경 이력

- v0.1: 승인된 프로토타입 범위의 공통 빌드·디자인·검증 규칙 작성. 실제 서비스 기술 선택은 미결로 유지.
