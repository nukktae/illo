## 멘토링 내용

## 📝 10/30 개발 멘토링 회의록

- **멘토:** 김범준 멘토
- **주제:** 일로 서비스의 AI 활용 개발 방식 및 협업·검증 체계 정리

### 📍 현재 진행 상황

- 프론트엔드 프로토타입 구현 및 Vercel 배포 완료
- 백엔드는 미구현 상태이며, 개발 역할 분담은 미정
- 기획·데이터 수집 흐름을 바탕으로 구체적인 개발 명세 작성 필요

### 💬 주요 논의 내용

**1. 개발 전 기획·설계 문서 구체화**

- 코드·디자인·회의록·설문·외부 데이터 등을 모아 AI가 서비스의 목적과 맥락을 이해하도록 제공
- **PRD(요구사항 정의서) → Spec(개발 명세) → 코드 생성** 순서의 개발 방식 권장
- PRD에는 문제 정의, 목표·제외 범위, 사용자 흐름, 기능 요구사항과 예외 상황을 명확히 작성

**2. PRD 세분화 및 역할 분담**

- 전체 구조와 하위 문서를 연결하는 상위 PRD를 두고, 페이지·기능별로 문서 분리
- 남은 일정을 고려해 우선 페이지 단위로 나누는 방식 권장
- 페이지 담당자가 프론트엔드·백엔드를 함께 맡는 방안 제안
- 작업을 식별할 수 있는 공통 ID·번호 체계를 마련하고, 구체적인 담당 범위는 팀에서 확정 필요

**3. 반복 검증 및 QA**

- AI가 작성한 PRD를 팀원이 직접 검토하고, 수정·보완을 반복
- 디자인이나 HTML 와이어프레임으로 화면과 이용 흐름이 의도대로 나오는지 확인
- PRD·Spec을 기준으로 정상·실패·예외 상황의 테스트 케이스 작성
- 버그 수정 후 기존 기능도 정상 동작하는지 재확인

**4. 발표 구성**

- **문제 정의 → 구현 서비스와 동작 → 기대 효과** 중심으로 구성
- 5분 발표에서는 상세한 기술·아키텍처 설명의 비중을 줄이고, 서비스가 문제를 어떻게 해결하는지 전달

### ✅ 후속 작업

- 기존 기획·회의록·조사 자료를 모아 PRD 구체화
- 페이지별 PRD 분리 및 역할 분담 기준 정리
- PRD 검토와 화면·와이어프레임 보완
- 기술 스택·API·DB·오류 처리 등을 포함한 Spec 작성
- 기능 구현과 테스트 진행 후, 막히는 부분을 다음 멘토링 질문으로 정리

※ 도구 도입과 페이지별 FE·BE 통합 담당 방식은 제안 단계이며, 팀 내 확정 필요.

## 🗨️ 물어볼 것 (우선순위 순)

> 1️⃣ **경험과 공고 비교를 어떻게 구현할지**
> 공고는 미리 역량 단위로 구조화해 두고, 사용자가 자유롭게 쓴 경험에서 역량과 근거 문장을 뽑아 맞추려고 합니다. 예: "동아리 인스타 운영 1년, 팔로워 300명 증가"가 공고의 "채널 운영 경험"에 해당하는지. 이 구조가 맞는지, LLM 한 번에 맡길지 단계를 나눌지 궁금합니다.

> 2️⃣ **최종 판단(교육 / 프로젝트 / 지원)을 누가 내리게 할지**
> 기획 멘토님은 "AI가 대신 결정하면 위험하다"고 하셨습니다. 충족한 필수 역량 비율 같은 규칙으로 나누고 AI는 근거 설명만 하는 게 나을지, 다른 방식이 있을지.

> 3️⃣ **공고 데이터 출처와 최신성**
> 고용24 채용정보 API는 개인회원이 쓸 수 없어 잡코리아, 링커리어에서 직접 수집한 공고를 씁니다. 시연과 발표에서 이렇게 써도 되는지, 출처와 수집 날짜를 어떻게 보여주면 될지.

> 4️⃣ **2분 시연의 범위와 안정성**
> 실제 LLM 호출로 돌릴지, 미리 만든 결과를 섞을지. 영상 제출(11/6)과 본선 라이브 시연에서 보통 어떻게 하는지.
