# Spec 쓰는 법

Spec(개발 명세)은 PRD를 **어떻게** 만들지 적는 문서예요. AI가 코드를 만들 때 넣는 설계도예요. PRD 리뷰가 끝난 뒤에 써요.

## 언제, 누가

- PRD가 팀 리뷰를 통과하면, 그 페이지 담당이 씁니다.
- 멘토 제안대로 한 사람이 페이지의 프론트와 백엔드를 함께 맡으니, Spec도 페이지당 한 장이에요.
- 파일: `docs/spec/P03-compare.md`처럼 PRD와 같은 이름. 틀은 [`docs/spec/_template.md`](../spec/_template.md).

## 먼저 팀이 정해야 하는 것 (공통 Spec)

페이지 Spec 전에 한 번만 정하고 `docs/spec/00-common.md`에 적어요. 안 정하면 네 명이 각자 다른 방식으로 만들어요.

- 기술 스택 (제안: Next.js App Router, TypeScript, Supabase, Vercel, Claude API)
- 폴더 구조, 이름 규칙, 코드 스타일
- 공통 DB 표 (users, resumes, postings, saved_items)와 누가 바꿀 수 있는지
- API 응답 모양과 오류 형식
- 디자인 토큰 (프로토타입과 같은 색, 반경, 글꼴)
- 테스트 도구와 PR 통과 조건

## 만드는 순서

1. `/spec-draft P03`으로 초안 (PRD, 공통 Spec, 프로토타입 화면 파일을 함께 넣어요).
2. 사람이 확인: PRD의 기능 ID가 Spec에 빠짐없이 있는지, 예외마다 처리 방법이 있는지.
3. 테스트 케이스: PRD 수용 기준 하나당 테스트 하나 이상. ID는 `P03-T01`.
4. AI를 쓰는 기능은 프롬프트, 출력 형식 (JSON 스키마), 시간 제한, 실패 처리, 지어낸 답 막는 방법을 꼭 적어요.

## 체크리스트

- [ ] PRD의 모든 기능 ID가 Spec 어딘가에 있다
- [ ] 화면마다 로딩, 빈 상태, 오류 상태가 있다
- [ ] DB 표와 API가 공통 Spec과 부딪히지 않는다
- [ ] 테스트가 정상, 실패, 예외를 다 다룬다
- [ ] 키는 환경 변수 이름만 적혀 있다 (값 없음)
