# AI로 코딩하기 (바이브 코딩 가이드)

멘토 말: AI는 정말 똑똑하지만, 우리 상황을 모르면 일을 잘하는 척하면서 엉뚱한 걸 만든다. 그래서 **맥락을 주고, 작게 시키고, 꼭 확인**해요.

## 기본 원칙 6가지

1. **맥락 먼저**: 시작할 때 `CLAUDE.md`, 맡은 PRD, Spec을 읽히세요. Claude Code는 `CLAUDE.md`를 자동으로 읽어요.
2. **문서가 먼저, 코드는 나중**: PRD에 없는 걸 만들고 싶으면 PRD부터 고쳐요.
3. **작게 시키기**: 한 번에 기능 ID 하나. "P03 다 만들어 줘" 대신 "P03-F02만".
4. **계획 먼저 보기**: 코드 전에 계획을 받아 읽고 고쳐요 (Claude Code의 plan 모드, `shift+tab`).
5. **테스트로 확인**: 기능마다 테스트를 같이 만들게 하고, 직접 실행해 결과를 봐요. "됐어요"라는 말만 믿지 않아요.
6. **화면은 눈으로**: PR 미리보기 링크에서 수용 기준을 하나씩 눌러 봐요. 프론트는 AI 테스트가 놓치는 게 많아요 (멘토).

## 하루 작업 흐름

```
1. git switch main && git pull
2. git switch -c p03-f02-ai-compare
3. Claude Code: /build-feature P03-F02
4. 계획 읽고 고치기  >  코드 생성  >  테스트 실행
5. /qa-cases P03-F02 로 빠진 테스트 확인
6. 커밋, push, PR (템플릿 채우기)
7. 미리보기 링크에서 확인, 리뷰 받기, 병합
```

## 명령어 (이 저장소에 들어 있어요)

Claude Code에서 `/`를 치면 보여요. 파일은 `.claude/commands/`.

| 명령 | 하는 일 |
|---|---|
| `/prd-draft P03` | 회의록, 조사, 화면을 읽고 PRD 초안이나 개정안 |
| `/prd-review P03` | PRD를 체크리스트로 검토하고 빠진 점 목록 |
| `/spec-draft P03` | PRD로 Spec 초안 |
| `/build-feature P03-F02` | Spec을 읽고 계획, 승인 뒤 코드와 테스트 |
| `/qa-cases P03-F02` | 수용 기준으로 테스트 케이스 (Given, When, Then) |

## 맥락 주는 법

- 파일은 `@`로 붙여요: `@docs/prd/P03-compare.md @docs/spec/P03-compare.md`
- 화면은 캡처를 붙여 넣거나 프로토타입 파일을 붙여요: `@prototype/S3-compare.html`
- 결정 이유가 필요하면 회의록을 붙여요: `@docs/meetings/transcripts/2026-10-30-팀회의-페이지구성.md`
- 너무 많이 붙이지 마세요. 관련 있는 것만. 많을수록 느리고 헷갈려요.

## 좋은 요청 예시

```
@docs/prd/P03-compare.md @docs/spec/P03-compare.md
P03-F03 판정 규칙(judge)만 만들어 줘.
- 입력: 공고 요구 문장, AI가 찾은 근거 문장 목록
- 규칙은 PRD 6번 표 그대로
- 근거 문장이 이력서 원문에 없으면 없음
- 먼저 계획과 테스트 목록만 보여 주고, 내가 OK하면 코드
```

## 나쁜 요청 예시

- "비교 기능 만들어 줘" (무엇을, 어디까지인지 없음)
- "알아서 예쁘게" (디자인 토큰, 화면 없음)
- "에러 나는데 고쳐 줘" (에러 메시지, 재현 방법 없음)

## 버그 고칠 때

1. 에러 메시지 전체와 재현 순서를 붙여요.
2. "원인부터 찾고, 고치기 전에 원인을 설명해 줘"라고 해요.
3. 고친 뒤 그 버그를 잡는 테스트를 추가하게 해요.
4. 다른 기능이 깨지지 않았는지 전체 테스트를 다시 돌려요 (멘토가 강조한 부분).

## 교차 확인 (시간 있을 때)

같은 PRD나 코드를 다른 AI(Codex, Gemini)에게도 리뷰시켜 서로 비교해요. 기준은 "PRD 기능이 다 들어갔나"부터. 버튼 위치 같은 건 뒤로.

## 절대 하지 말 것

- 키, 토큰을 프롬프트나 코드에 붙이기 (`.env`의 이름만 쓰기)
- 개인정보가 든 파일을 AI에 통째로 넣기
- AI가 만든 코드를 읽지 않고 main에 병합
- 테스트를 지워서 통과시키기
