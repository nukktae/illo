# P04 PRD 검증 기록

최초 검토 2026.11.01 (v1.2) · 추가 검토 2026.11.02 (v1.7) · 대상 [P04 PRD](../prd/P04-education.md) · 담당 이민섭

**판정: 제품 동작은 구체화했으며, 팀 승인·연계 Spec·데이터 준비는 미완료.** v1.7 기준 기능 19개와 수용 기준 67개로 Spec 작성 입력을 정리했다. 실제 로그인·계정별 서버 저장은 사용자가 확정했지만 공통 인증·저장·비교 문맥의 구현 계약은 남아 있으므로 통합 개발 준비가 끝났다고 판단하지 않는다.

## 1. 검증 범위

- 사용자가 확정한 범위·역할·로그인 후 저장 조건과 PRD 일치 여부.
- P01~P06·00-root·PRD/Spec 작성 가이드와 페이지 간 요구사항 대조.
- 교육 CSV 210개, 화면용 과정 JSON 210개, 정책 원본 1,476개와 화면용 213개의 필드·상태·식별자 확인.
- 데이터 변환 코드, 교육·다음 행동·공통 저장·시연 로그인 화면 소스 검토.
- 대표 SeSAC 공식 상세와 온통청년 공식 코드 정의서 확인.

브라우저 사용성 테스트·실제 로그인·저장·API 기능 테스트는 수행하지 않았다. 이번 변경은 PRD와 검증 기록이며 데이터·프로토타입 동작은 수정하지 않았다.

## 3. 원본 대조 수치

### 교육

- 원본·화면용 자료 모두 210개, 화면용 식별자 중복 0건.
- 원본 상태: 모집 중 15, 모집 예정 7, 운영 중 30, 운영 대기 1, 종료 144, 상시 13.

- 현재 화면용 자료는 모집 시작일을 보존하지 않는다. 전체 상세와 추천 근거를 추가 조사해야 한다.

213개 화면용 정책 모두 원본의 `plcyNo`로 연결되며 식별자 중복은 없다.

| --- | --- | --- |
| 신청 중 | 12 | 12 |
| 상시 | 121 | 38 |
| 마감 | 80 | 163 |

공식 코드 의미는 특정기간 `0057001`, 상시 `0057002`, 마감 `0057003`이다. 기간이 없는 121건 중 83건이 마감 코드인데도 기존 변환 코드에서 상시로 분류된다. 이는 실제 변환 오류다. 대조 결과의 신청 중·상시 50건도 현재 예산 소진·별도 종료 여부까지 확인한 결과는 아니다. [온통청년 공식 코드 정의서](https://www.youthcenter.go.kr/downloadform/API%EC%BD%94%EB%93%9C%EC%A0%95%EB%B3%B4.xlsx)

- 원본에는 쉼표로 여러 분야가 기재된 항목 5건이 있다. 같은 분야가 반복된 2건과 서로 다른 분야를 가진 3건을 구분해 중복 제거해야 한다.

## 5. Spec 작성자가 바로 사용할 입력

1. PRD 1~3절: 목표·대상·범위.
2. 4~10절: 진입·상태 전이·검색/정렬·상세·저장·실패 동작.
3. 11절: 논리 데이터·기존 자료·보강 필드·검수 조건.
4. 12절: 기능과 연결된 수용 기준 67개.

가장 먼저 해결할 것은 **G01~G03의 페이지 간 계약**, **G05의 상세·추천 근거 자료**, **G06의 정책 상태 오분류**다. 미결 사항을 임의의 DB·인증 방식·예시 추천으로 메우지 않는다.

| 경력 이직 + 명시적 보완 선택 없음 | 관심 학습과 일반 목록, 선택 없이도 검색 가능 | AC52 |
| 완료된 유효 비교의 보완 후보 0개 | 해당 공고·입력 범위의 보완 미확인 안내, 관심 학습 | AC53 |
| 분석 미완료·실패·전부 비교 제외·목적 미상 | 보완 없음으로 오인하지 않고 상태별 안내와 일반 탐색 | AC54 |
| 이미 가진 역량을 더 배우려는 관심 선택 | 직접 선택과 수업 근거로 관련 교육 제공, 부족 진단 표시 없음 | AC55 |
| 직접 변경·전체 해제·P03 명시 선택 | 사용자 의도가 자동 기본값보다 우선 | AC56~57 |
| 두 목적 전환·학생/재직 등 상태 중첩 | 목적별 선택 분리, 현재 명시적 지원 목적과 사용자 선택 우선 | AC58 |

공고 보완에는 비교·공고 근거가 필요하고, 관심 학습에는 직접 선택과 검수된 교육 근거가 필요하다. 관심 학습 때문에 이직 공고 분석이나 다른 직무 AI 분석을 P02·P03에 새로 구현하는 것으로 범위를 넓히지 않는다. 현재 지원 목적은 전달 가능한 경우에만 사용하며 미확인 사용자를 강제 분류하지 않는다.

새 학습 역량 선택 목록도 검수된 교육 매핑 범위에서만 제공한다. 실제 후보·지원 목적의 전달은 G02, 검수 자료 준비는 G05에 남아 있으며 해당 팀 합의·데이터 준비를 완료한 상태는 아니다.


## 8. 로그인 후 자동 북마크 사용자 확정

- 사용자 확정: 비로그인 상태에서 북마크를 요청한 뒤 로그인에 성공하면 원래 화면으로 복귀해 해당 항목을 한 번 자동 저장한다. 재클릭을 요구하지 않는다.
- 이미 저장된 항목은 유지하며, 반복 콜백·응답 재시도로 중복 저장하거나 해제하지 않는다. 실패·취소·만료·삭제된 대상의 처리는 기존 예외 기준을 유지한다.
- PRD 확정 표·진입 흐름·8.2절·AC31·G03에 반영했다. G03에는 자동 저장 여부가 아니라 실제 인증·저장·복귀·회원가입 연계 계약이 남는다.


## 9. 정책 첫 화면 사용자 확정

- 신청 중·상시 신청으로 확인된 정책을 먼저 제공하고 전체 정책도 볼 수 있게 하기로 사용자가 확정했다.
- 신청 가능만 기본 켜짐, 전체 보기 시 검색/기관/분야 유지, 탭 복귀 시 사용자 필터 복원, 초기화 시 기본 켜짐으로 복원을 명시했다.
- 마감·예정·확인 필요 상태는 전체 보기에서 해당 상태로 탐색 가능하며 신청 가능 CTA로 바꾸지 않는다. 신청 가능 0건을 필터 해제나 마감 정책으로 자동 대체하지 않는다.
- 탭/분야/결과 개수의 적용 기준과 AC59~AC60을 추가했다. 실제 데이터 오분류 수정·동작 검증은 아직 완료하지 않았다.


## 10. 상태 확인 주기·유효기간 사용자 확정

- 하루 한 번 모집·신청 상태를 확인하고 마지막 성공 확인 후 48시간 이상이면 확인 필요로 바꿔 추천·신청 가능 목록에서 제외하기로 확정했다.
- 실제 경과 시간의 48시간 경계, 확인 시각 누락/해석 불가/미래, 기존 파일 재생성만 한 경우, 갱신 실패와 성공 후 재판정을 구분했다.
- 마지막 원본 상태·기존 저장 항목은 보존한다. 만료된 과정의 기존 상세와 정책 전체 보기는 확인 필요 안내·공식 정보 링크로 열람 가능하다.
- 상태 확인일과 교육 근거 검수일을 분리한다. 매일 상태를 확인했다고 교육 내용까지 재검수한 것으로 기록하지 않는다.
- AC61~AC63과 G04를 갱신했다. 실제 수집 일정·실패 알림·담당자 구성은 아직 미완료이며 이 작업에서 예약 작업이나 수집 코드를 생성하지 않았다.


## 11. 담당자 공유·합의 상태 확인

2026.11.02 사용자 답변으로 상혁·준석과 아직 공유·합의 전임을 확인했다. P04에서 확정한 제품 동작과 상대 담당자의 구현 합의는 구분한다. G01~G03·13.5의 계약은 제안 상태이며 입력 예제·책임 범위·실패/복귀 결과를 합의한 뒤에만 완료로 바꾼다.

PRD에 두 담당자와 먼저 확인할 질문과 합의 후 남길 결과를 추가했다. 실제 메시지를 보내거나 다른 페이지 PRD를 수정하거나 팀 승인으로 기록하지 않았다. 현재 독립 화면의 Spec 초안 준비는 가능하나 비교·인증·저장 통합 Spec 준비는 아직 미완료다.

### 충분한지에 대한 결론

**P04 내부의 공개 탐색·상세·정책 요약과 목적별 추천 동작은 Spec 초안 작성에 충분하다. 실제 통합 개발 준비 완료 상태는 아니다.** 제품 선택을 더 임의로 늘리기보다 다음 준비물을 완료해야 한다.

1. G01~G03·G07: 상혁·준석·아노와 페이지 책임·비교 입력·실제 인증·서버 저장·회원가입 복귀를 맞춘다.
2. G05: SNS·마케팅 첫 지원 역량의 공통 ID·정의·표시명·검수 상태와 교육 연결 근거, 전체 노출 과정 상세를 준비한다.
3. G06: 기존 정책 상태 83건 오분류와 복수 분야·검색 원문 유실을 실제 데이터 변환에서 고친다.
4. G04·G08: 하루 한 번 확인·48시간 만료의 운영 담당/실행/실패 알림과 시연용 주·대체 과정을 준비한다.

위 항목을 완료한 것으로 표시하지 않았으며 상대 담당자의 PRD·구현 코드·데이터를 이번 검토에서 수정하지 않았다.

## v1.7 Spec·개발 착수 재검토 (2026.11.02)

판정: P04 내부 Spec 작성은 가능하다. 전체 기능을 그대로 구현하는 개발 지시서로 사용하기에는 공통 계약과 실제 자료가 미완료다.

- 제품 범위·두 학습 목적·추천/일반 탐색 구분·정책 기본 필터·실패/빈 결과·상태 유효기간·저장 재개·수용 기준은 작성돼 있다. 추가 제품 기능을 정하기 위해 PRD를 계속 확장할 필요는 없다.
- 현재 P03-F08은 지난 과정 전환을 포함하며, P05는 계정 서버 저장을 제외하고 P06은 예시 계정 인증을 명시한다. P04와의 충돌이 실제 문서에 남아 있어 G01~G03 합의 없이 통합 구현하면 안 된다.
- G05의 실제 지원 역량 목록·과정 상세·검수 매핑과 G06의 정책 변환 오류 수정은 아직 완료 근거가 없다. 화면 제작용 예제 자료를 실제 추천·정책 기능 완성으로 간주하지 않는다.
- Spec은 화면별 상태와 전이, 실제 입력/출력 예제, 필드·검증 규칙, 응답/오류, 저장 재개의 중복 방지·계정 전환·만료 처리, 복원 범위와 상태 우선순위, 상태 재평가 시점, AC별 검증 방법을 확정해야 한다. 이는 PRD에 API·DB 구현을 추가할 문제가 아니라 Spec의 설계 작업이다.
- 공개 탐색·공통 상세·정책 요약의 독립 Spec부터 작성한다. 승인된 Spec과 검증용 자료로 화면 개발은 가능하되 실제 데이터 연결에는 G05~G06을, 비교·저장 통합에는 G01~G03을 선행한다. 운영·출시 준비는 G04·G07~G08까지 별도로 확인한다.

이번 재검토는 로컬 문서 대조다. 공식 사이트 재확인·실제 인증/저장 테스트·팀 합의는 수행하지 않았다.
