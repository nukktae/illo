# P02 직무 찾기 PRD

버전 v1.4 초안 (2026.11.02) | 상태: PR #6 모바일 배치 개정안 팀 확인 완료·Spec v0.4 작성 완료·리뷰 반영 구현·로컬 검증 완료. 기존 정렬·이력서 상태 구현 이력 유지 | 상위 문서: [00-root.md](00-root.md)

이번 개정은 P02-F05·P02-F06과 신규 P02-F08의 프로토타입 동작에 한정한다. 실제 P05 이력서 저장·연동과 7개 직무의 사용자별 역량 분석은 미구현 의존성으로 유지한다 (2026.11.02 사용자 범위 승인).

## 1. 요약

직무를 고르고, 그 직무의 공고 목록에서 비교할 공고를 고른다. 신입과 인턴에게는 내 경험으로 본 직무 역량을 먼저, 경력에게는 공고 비교를 바로 보여 준다.

## 2. 왜 필요한가

- 10/30 회의: 신입과 인턴은 어떤 직무가 맞는지부터 알고 싶고, 경력자는 고른 공고와 바로 비교하고 싶다.
- 2026.11.02 사용자 결정: 7개 직무 모두 경험과 겹치는 역량이 많은 공고부터 보며, 이력서 미등록 시 개인화 결과 대신 등록 안내를 표시한다.
- 공고는 실제로 100건이 넘는다. 검색, 필터, 정렬, 페이지가 필요하다.

## 3. 목표

- 7개 직무 중 하나를 골라 공고 목록을 본다.
- 공고 하나를 골라 P03 비교로 간다.

## 4. 하지 않는 것

- 실제 이력서 저장·P05 연동, 공고 원문에서 역량을 추출하는 신규 AI/API·수집 파이프라인은 이번 프로토타입 변경 범위 밖이다.
- SNS 콘텐츠 마케팅 외 6개 직무도 겹치는 역량 수 정렬 정책은 동일하게 적용한다. 실제 역량 분석·상단 AI 역량 카드 확장·공고 문장 비교는 이번 범위 밖이며 준비 중 상태를 유지한다.
- 현재 사전 작성된 이력서에 대응하는 기존 SNS 역량 수는 프로토타입에서 표시한다. 이를 새로 입력한 사용자의 실제 분석 결과로 오인하지 않도록 구분하며, 다른 직무의 미분석0은 분석 완료로 취급하지 않는다.
- 경력 공고 목록 (이번 범위 밖)

### 사용자 이야기

- 구직자로서 선택한 직무에서 내 경험과 겹치는 역량이 많은 공고부터 확인하고 싶다.
- 이력서를 등록하지 않은 사용자로서 실제 분석되지 않은 숫자 대신 등록 안내를 보고 싶다.

### P02-F01·P02-F06 모바일 탐색 배치 (v1.4)

- [PR #6 리뷰](https://github.com/nukktae/illo/pull/6#issuecomment-6577141345)에 따라 모바일은 선택 직무 제목·공고 수를 먼저 보여 주고 그 아래에 기존 7개 직무 선택·직무 검색을 배치한다. 데스크톱 배치는 유지한다.
- 직무 버튼은 한 줄 가로 스크롤을 유지하고 검색·선택·필터·정렬·페이지 초기화 동작을 변경하지 않는다. 제목과 선택 직무·목록은 일치해야 한다.
- 제목 아래로 위치만 옮겼다고 첫 공고가 더 빨리 보이는 것으로 간주하지 않는다. 동일 뷰포트의 첫 공고 위치·전체 높이를 변경 전후 측정하고, 첫 공고가 더 아래로 밀리지 않으며 가로 넘침·누락이 없는지 확인한다. 불필요한 여백 수치는 Spec에서 정한다.

### P02-F05 추천순과 다른 직무 적용

- SNS 콘텐츠 마케팅과 나머지 6개 직무 모두 동일한 정렬 정책을 사용한다. 추천순은 **공고 요구 역량과 사용자 경험 역량의 교집합에서 중복을 제외한 개수**의 내림차순이다. 동일 역량의 반복 언급을 여러 개로 세지 않는다.
- 동점은 최신순으로 정렬한다. 추천순에서만 선택 직무·검색·필터에 맞는 시연 공고를 먼저 배치한다. 최신순·마감 임박순에는 시연 공고 우선 규칙을 적용하지 않는다. 나머지 공고에 해당 정렬을 적용한다. 시연 공고가 여러 개이면 시연 공고끼리도 해당 정렬을 따른다. 검색·필터에 맞지 않는 시연 공고는 끼워 넣지 않는다 (2026.11.02 사용자 변경 승인 및 팀 리뷰 완료 보고). 날짜까지 같거나 없는 경우 순서가 임의로 바뀌지 않도록 안정적인 순서를 유지한다.
- 검색·고용형태 필터를 적용한 전체 결과를 정렬한 뒤 10개씩 나눈다. 직무·검색·필터·정렬 변경 시 첫 페이지로 이동한다. 최신순·마감 임박순의 기존 기능은 유지한다.
- 이력서 미등록이면 개인화 추천을 제공하지 않는다. 추천순을 선택한 경우 실제 목록은 최신순으로 표시하고 “이력서를 등록하면 겹치는 역량 순으로 볼 수 있어요. 현재는 최신순이에요”라고 안내한다. 다른 정렬을 선택하면 해당 정렬을 따른다.
- 등록 상태이나 미분석인 공고는 분석 완료 0개와 구분한다. 추천순에서 분석 완료 공고 뒤에 두고 미분석끼리는 최신순으로 표시한다. 전부 미분석이면 “역량 분석 준비 중이에요. 현재는 최신순이에요”라고 안내한다.

### P02-F06·P02-F08 공고 행 표시

- 미등록 시 기존 “내 경험과 겹치는 역량 N” 위치에 **“이력서를 등록해주세요”** 박스를 표시한다. 회색 배경 `#F2F4F6`, 글자 `#4E5968`, 기존 칩과 같은 반경6px·글자12px·여백3px 8px를 사용한다. 새 버튼이나 이동 동작을 요구하지 않는다.
- 등록·분석 완료이면 “내 경험과 겹치는 역량 N”을 표시한다. N=0도 숨기지 않고 “내 경험과 겹치는 역량 0”으로 표시한다. 등록됐지만 미분석이면 숫자 대신 회색 “역량 분석 준비 중” 박스를 표시한다.
- 상단 역량 카드 역시 미등록 상태를 사용자 분석 완료처럼 보여 주지 않는다. 사용자 체크·일치 요약 대신 미등록 안내를 표시하며 기존 일반 직무 정보와 공고 탐색은 유지한다.
- 데스크톱·모바일과 7개 직무에서 같은 상태 정책을 적용한다. 기존 비교하기·원문·저장 동작은 유지한다.

### 이번 프로토타입의 데이터 경계

- **마이페이지 → 이력서 등록에 내용이 있는지**를 기준으로 한다. 현재 사전 작성된 이력서는 내용 있음 상태다. 서버 저장 여부·저장 버튼 클릭 여부를 이유로 내용 있는 이력서를 미등록으로 처리하지 않는다.
- 이력서 내용이 모두 비어 있을 때만 회색 “이력서를 등록해주세요”를 표시한다. 일부 항목이 비어 있거나 연락처가 누락돼도 다른 이력서 정보가 있으면 내용 있음이다. placeholder·입력 안내·추천 스킬은 작성된 내용으로 세지 않는다.
- 현재 기본 화면에서는 기존 SNS 공고의 사전 이력서 기준 겹치는 역량 수를 복원한다. 다른 직무는 이력서 내용이 있어도 실제 분석값이 없으므로 “역량 분석 준비 중”으로 구분한다.
- 등록·분석 완료·0개·미분석과 정렬 검증은 **별도 테스트 자료**로 수행한다. 7개 직무에 같은 정렬 로직이 적용되는지는 테스트하되, 제품의 실제 공고에 임의 역량 수를 채우지 않는다.
- P05 저장 버튼을 누르지 않아도 사전 작성된 내용이 있으면 내용 있음으로 표시한다. 현재 P05의 편집·저장이 다른 화면으로 전달되지 않는 한계는 별도 의존성이다. 내용을 전부 지운 뒤 P02로 이동했을 때의 연동까지 완료됐다고 선언하지 않는다. 실제 편집 상태 연결이 필요하면 P05 담당 범위와 함께 명세·검증해야 한다.

## 8. 수용 기준

- **Given** 모바일 직무 찾기에서 **When** 7개 직무를 차례로 선택하면 **Then** 제목·공고 수 → 직무 버튼·검색 순서가 유지되고 선택 직무와 목록이 일치한다.
- **Given** 동일 기본 자료와 390px/320px 뷰포트에서 **When** 배치 변경 전후를 비교하면 **Then** 첫 공고 위치가 더 아래로 밀리지 않고 제목·버튼·검색이 잘리거나 페이지 가로 넘침이 없다. 측정값을 테스트 기록에 남긴다.

- **Given** 직무 찾기에서 **When** "AI 엔지니어"를 누르면 **Then** 제목이 바뀌고 그 직무 공고가 10개씩 보인다.
- **Given** 목록에서 **When** "마감 임박순"을 누르면 **Then** D-day가 작은 공고가 위로 온다.
- **Given** "회계"를 직무 검색하면 **Then** "아직 준비 중이에요"가 보인다.

### 이번 개정 수용 기준 (데스크톱·모바일 공통)

- **Given** 등록·분석 완료 테스트 자료에서 겹치는 고유 역량 수가 1·3·2인 공고가 있을 때 **When** 추천순을 선택하면 **Then** 시연 공고가 먼저 나오고 일반 공고는 3·2·1 순서다. 최신순·마감 임박순에서는 시연 여부와 무관하게 해당 정렬 기준을 따르며, 시연 공고가 검색·필터에서 제외되면 표시하지 않는다. 7개 직무에 각각 적용한다.
- **Given** 같은 역량이 여러 번 언급된 자료에서 **When** 겹치는 수를 계산하면 **Then** 동일 역량은 한 번만 센다.
- **Given** 겹치는 수가 같은 공고에서 **When** 추천순을 선택하면 **Then** 최신 공고가 먼저 나오고 날짜 없음·완전 동점에서도 순서가 안정적이다.
- **Given** 10개 넘는 결과에서 **When** 검색·필터·추천순을 적용하면 **Then** 전체 결과를 정렬한 후 페이지를 나누며 조건 변경 시 첫 페이지로 돌아온다.
- **Given** 이력서 미등록 상태에서 **When** 어느 직무 목록을 열면 **Then** 공고 행의 역량 위치에 회색 “이력서를 등록해주세요”가 보이고 실제 개인화 숫자·상단 사용자 체크는 보이지 않는다.
- **Given** 미등록 상태에서 **When** 추천순을 선택하면 **Then** 최신순으로 표시되며 대체 안내가 보인다. 최신순·마감 임박순을 선택하면 해당 기준을 따른다.
- **Given** 등록 테스트 상태에서 분석 완료 0개와 미분석 공고가 섞여 있을 때 **When** 목록을 확인하면 **Then** 0개는 숫자로, 미분석은 “역량 분석 준비 중”으로 구분하며 추천순에서 미분석은 분석 완료 뒤에 온다.
- **Given** 등록됐으나 모든 공고가 미분석일 때 **When** 추천순을 선택하면 **Then** 최신순 목록과 분석 준비 중 안내를 표시한다.
- **Given** 마이페이지에 현재 사전 작성된 이력서가 있을 때 **When** SNS 목록에 진입하거나 저장 후 복귀하면 **Then** 회색 등록 안내 대신 기존 사전 이력서 기준 “내 경험과 겹치는 역량 N”을 표시한다.
- **Given** 이력서 내용이 전부 비어 있는 상태에서 **When** 목록을 열면 **Then** 회색 등록 안내를 표시한다. 일부 내용이 남아 있으면 미등록으로 처리하지 않으며, placeholder·안내문만 있는 경우는 빈 상태다. 실제 P05 편집·삭제 후 이동 검증은 상태 전달 의존성과 분리해 기록한다.
- **Given** 좁은 모바일에서 **When** 안내 칩과 기존 저장·비교하기·원문을 확인하면 **Then** 문구 잘림·겹침이 없고 기존 동작은 유지된다.

## 11. 바뀐 점

- v1.5 (2026.11.02): 데스크톱 상단 정리. 제목과 신입, 경력 전환을 맨 위에 두고, 직무 고르기를 칩에서 밑줄 탭 줄로 바꿨다. 트렌드 보기는 공고 수 옆으로 옮겼다. 역량은 누를 수 있는 칩처럼 보이지 않게 번호 목록으로 바꿨다. 모바일은 그대로다. 이어서 데스크톱 제목 아래 공고 건수 줄 ("신입, 인턴 공고 46건", "경력 공고 22건")을 빼고, "이 직무 트렌드 보기"는 많이 찾는 역량 카드 오른쪽 끝 (경력은 경력 안내 카드 오른쪽 위)으로 옮겼다. 건수는 목록의 "46건 중 1~10"에 남는다. 경력 안내도 많이 찾는 역량과 같은 한 줄 카드 (왼쪽 굵은 제목, 짧은 설명, 오른쪽 트렌드 보기)로 맞췄다.
