# P03 공고 비교와 다음 행동 PRD

버전 v1.2 초안 (2026.11.01) | 상태: P03-F13·P03-F14 사용자 개정안 확인 완료, 팀 검토 대기 | 상위 문서: [00-root.md](00-root.md) | 우선순위: **실제 구현 1순위**

이번 개정 범위는 P03-F14이며, 이전 개정 P03-F13도 팀 검토 대기다. P03-F13의 선행 코드 변경은 철회했고 P03-F14는 문서만 작성했으므로 두 기능 모두 구현 완료 상태가 아니다. 팀원 1명 PRD 리뷰 후 Spec을 작성하고, 구현 계획 확인 → 코드·테스트 → PR 리뷰 순서로 진행한다.

## 1. 요약

공고 원문을 그대로 보여 주고, 사용자가 저장한 이력서를 근거로 공고 문장마다 맞음, 일부, 없음을 표시한다. 오른쪽 패널에는 점수와 다음 행동 4가지를 둔다. 다음 행동을 고르면 교육, 자격증과 어학, 대외활동과 프로젝트, 지원 준비 화면으로 간다.

## 2. 왜 필요한가

- 사용자는 "내 경험이 이 공고에 맞나"를 알고 싶지만, 지금은 공고를 읽고 혼자 짐작한다.
- 1차 기획 멘토: AI가 개인에게 판단을 내려 주는 건 위험하다. 근거를 보여 주고 선택은 사용자가 해야 한다.
- 이 기능이 해커톤에서 AI를 쓰는 핵심 지점이다.
- P03-F13: 자격요건의 트렌드를 확인하려고 공고 목록으로 이동하면 보고 있던 비교 결과를 이어 읽기 어렵다. 비교 화면에서 연 트렌드는 닫은 뒤 같은 비교 결과를 계속 볼 수 있어야 한다 (2026.11.01 사용자 화면 첨부 요청 및 동작 확인).
- P03-F14: 비교 전 패널의 경험 카드 안에 있는 "이력서 수정" 링크가 작아 찾고 누르기 어렵다는 사용자 의견이 있었다. "AI로 비교하기"와 같은 크기의 "나의 이력서 수정" 버튼으로 변경한다 (2026.11.01 사용자 요청, 대화에서 제시한 와이어프레임과 문구 수정안 승인).

## 3. 목표

- 공고 문장 단위로 근거를 보여 줘서, 사용자가 왜 맞음이고 왜 없음인지 이해한다.
- 비교 결과에서 다음 행동 하나를 고르게 한다.
- P03-F13: 트렌드를 확인한 뒤 재비교 없이 같은 공고와 비교 결과를 이어서 본다.
- P03-F14: 비교에 쓰일 경험을 확인한 사용자가 비교 전에 이력서 수정으로 쉽게 이동한다.

## 4. 하지 않는 것

- 합격 여부, 합격 확률, 점수 순위를 말하지 않는다.
- 이력서 문장을 새로 지어내지 않는다. 문장 다듬기는 입력한 사실의 순서만 바꾼다.
- 관심, 태도 문장 (예: "뷰티 산업에 대한 애정")은 비교하지 않고 그렇게 표시한다.
- P03-F13에서는 트렌드 데이터·순위·출처·디자인, 실제 수집 주기, AI 비교·판정 로직을 바꾸지 않는다. 기존 화면의 "실시간 공고 키워드" 명칭이 실시간 수집 구현을 뜻하지 않는다.
- P03-F13은 비교 화면 내 팝업 열기·닫기만 변경한다. 다른 진입점의 이동, 공고 목록 링크, 새로고침·브라우저 뒤로 가기의 상태 보존 방식은 변경하지 않는다.
- P03-F14에서는 이력서 입력·저장, AI 비교 로직, 수정 후 자동 복귀·자동 재비교를 새로 구현하지 않는다. 비교 결과의 문장 아래에 있는 "이력서 고치기" 링크와 P05 화면은 변경하지 않는다.

## 5. 사용자 이야기

- 취업 준비생으로서, 공고 원문 옆에서 내 경험과 맞는 문장을 바로 보고 싶다.
- 취업 준비생으로서, 비어 있는 요구마다 무엇을 하면 채울 수 있는지 알고 싶다.
- 취업 준비생으로서, 다음에 할 일을 내가 고르고, 그 선택을 저장하고 싶다.
- 취업 준비생으로서, 자격요건의 트렌드를 확인한 뒤 창을 닫으면 방금 보고 있던 공고와 비교 결과를 그대로 이어 보고 싶다.
- 취업 준비생으로서, 비교에 쓰는 경험을 확인하다 수정이 필요하면 눈에 잘 보이는 "나의 이력서 수정" 버튼으로 이력서 화면에 가고 싶다.

### P03-F13 상세 동작과 영향 범위

- 진입 위치는 비교 결과의 자격요건 → Skillset → "최신 콘텐츠 트렌드와 밈(Meme)에 관심" 항목 아래 "트렌드 보기"다. 비교 전 화면에는 이 기능을 위한 새 버튼을 추가하지 않는다.
- 클릭 시 현재 비교 페이지에 팝업을 겹쳐 표시한다. 공고 목록으로 이동하거나 비교 페이지를 다시 불러오지 않으며, 현재 URL도 바꾸지 않는다.
- 팝업의 내용·순위·출처는 기존 트렌드 팝업과 같고, 비교 페이지에서만 하단 버튼을 "공고 비교로 돌아가기"로 표시한다.
- X와 하단 버튼은 모두 팝업만 닫는다. 열기 전의 공고, 비교 완료 상태, 문장별 표시·근거, 결과 패널을 유지하며 다시 비교하거나 이력서를 다시 입력하게 하지 않는다.
- 팝업을 다시 열고 닫아도 동일하게 동작한다. 배경 클릭·Escape 등 새로운 닫기 방법은 이번 범위에 추가하지 않는다.

| 진입점 | X로 닫기 | 하단 행동 | 변경 여부 |
|---|---|---|---|
| P03 비교 결과의 Skillset | 동일 비교 화면·결과 유지 | "공고 비교로 돌아가기": 팝업만 닫기 | 이번 변경 |
| P02 공고 목록 | 목록 유지 | "공고 목록으로 돌아가기": 팝업만 닫기 | 기존 유지 |
| P01 홈의 키워드 전체 보기 | 홈 유지 | "이 직무 공고 보기": 공고 목록으로 이동 | 기존 유지 |
| 기존 트렌드 전용 주소 | 기존처럼 목록의 트렌드 팝업으로 연결 | 공고 목록으로 복귀 | 기존 유지 |

위 표는 데스크톱·모바일에 동일하게 적용한다. 다른 진입점의 "기존 유지"는 현재 코드의 동작 기준이다. 홈의 X까지 목록 이동으로 바꾸는 요구가 아니다. 연관 요구사항: P01-F04, P02-F07. 근거: `design/screens/10_home.py`, `20_job_search.py`, `01_base.py`, `design/scripts/export_static.py` (2026.11.01 변경 전 코드).

### P03-F14 상세 동작과 화면 구성

- 대상은 "직무 찾기 → 비교하기"로 들어온 **비교 전 패널**이다. 데스크톱에서는 오른쪽 패널, 모바일에서는 기존 비교 전 패널 위치에 적용한다.
- 표시 순서: 안내 제목 → "비교에 쓰는 내 경험" 카드 → "나의 이력서 수정" → "AI로 비교하기" → 기존 AI 안내 문구.
- 경험 카드 안의 작은 "이력서 수정 ›" 링크를 제거한다. 카드 제목과 경험 요약은 유지한다.
- 두 버튼은 각각 패널 내부 가용 너비 전체를 사용하며 높이는 **54px**, 버튼 사이 세로 간격은 **8px**로 한다. 모서리 반경 14px, 글자 크기 17px·굵기 600과 중앙 정렬을 동일하게 적용한다. 높이·반경·글자 기준은 현재 AI 비교 버튼에 맞춘다 (`design/screens/30_compare.py`, 2026.11.01 기준).
- "나의 이력서 수정"은 연한 회색 배경 `#F2F4F6`과 진한 글자 `#191F28`, "AI로 비교하기"는 기존 강조색 `#3182F6`과 흰 글자를 사용한다. 두 버튼 크기는 같지만 주요 행동의 파란색 강조는 AI 비교에만 둔다 (`CLAUDE.md` 디자인 원칙).
- "나의 이력서 수정"을 누르면 기존 P05 이력서 등록·수정 화면으로 이동한다. 프로토타입 기준 데스크톱은 `/S5-resume.html`, 모바일은 `/m-S5-resume.html`이다. AI 비교를 실행하는 버튼이 아니다.

## 7. 예외와 빈 상태

| 상황 | 처리 |
|---|---|
| 이력서가 없음 | 비교 버튼 대신 "이력서를 먼저 등록해 주세요" 와 이력서 등록 버튼 |
| AI 응답 실패, 시간 초과 (10초) | "비교하지 못했어요. 다시 시도" 버튼. 이전 결과가 있으면 그대로 보여 준다 |
| AI가 근거 문장을 지어냄 | 근거 문장이 이력서 원문에 실제로 있는지 문자열로 확인하고, 없으면 없음으로 처리 |
| 공고 문장이 6개보다 많거나 적음 | 개수는 공고에 따라 바뀐다. "N개 중 M개" 로 표시 |
| 관심, 태도 문장 | 비교 제외 표시 |
| P03-F13: 아직 비교 결과가 없음 | 기존 비교 전 화면 유지. 트렌드 진입을 위해 비교 완료로 바꾸거나 새 버튼을 추가하지 않음 |
| P03-F13: 팝업을 반복해서 열고 닫음 | 한 팝업만 표시하고 동일 공고·비교 결과 유지 |
| P03-F13: 비교 화면을 직접 열어 비교한 경우 또는 기존 결과 진입 | 이전 방문 페이지와 무관하게 현재 비교 화면에 남음. 방문 기록에 의존해 다른 페이지로 복귀하지 않음 |
| P03-F14: 이력서가 없음 | 이 문서의 기존 이력서 없음 안내·등록 버튼 정책을 따른다. 두 버튼 와이어프레임은 경험이 표시된 비교 전 상태이며, 빈 이력서를 실제 경험처럼 표시하거나 비교를 허용하는 요구가 아님 |
| P03-F14: 경험 요약이 길거나 모바일 너비가 좁음 | 요약은 카드 안에서 줄바꿈하고, 두 버튼은 카드 밖에서 같은 너비·높이와 8px 간격을 유지. 버튼 문구가 잘리거나 서로 겹치지 않음 |
| P03-F14: 비교 결과 표시 상태 | 새 수정 버튼을 결과 패널에 추가하지 않음. "다시 비교"로 비교 전 패널이 표시되면 같은 배치 적용 |

- P03-F13: 기존 트렌드 팝업의 데이터·출처를 그대로 사용한다 (`design/screens/00_mobile_parts.py`의 순위와 `01_base.py`의 팝업, 2026.11.01 코드 기준). 신규 API·수집·통계 계산은 요구하지 않는다.
- P03-F13에서 유지할 화면 상태: 현재 공고, 비교 완료 여부, 문장별 표시·근거와 결과 패널. 팝업 표시 여부는 비교 결과를 변경하지 않는다. 저장소·서버의 영속 저장은 이 기능 범위가 아니다.
- P03-F14: 경험 요약과 이력서 이동 대상을 그대로 사용한다. 신규 데이터·API는 없다. 입력·저장의 책임은 [P05-F02·P05-F03](P05-mypage.md)에 있으며, 이번 개정은 P03의 수정 진입 버튼 표시만 바꾼다.

## 9. 수용 기준

- **Given** 이력서가 저장된 사용자가 공고 페이지에 있을 때 **When** "AI로 비교하기"를 누르면 **Then** 10초 안에 공고 문장마다 표시가 생기고 오른쪽에 "6개 중 2개가 이어져요"가 보인다.
- **Given** 비교 결과가 있을 때 **When** 없음 표시 아래 "프로젝트"를 누르면 **Then** 대외활동과 프로젝트 화면으로 간다.
- **Given** 비교 결과가 있을 때 **Then** 화면 어디에도 합격, 확률, 점수라는 말이 없다.
- **Given** AI가 이력서에 없는 문장을 근거로 돌려줄 때 **Then** 그 항목은 없음으로 표시된다.
- **Given** 교육으로 배우기 화면에서 **When** "지난 과정 포함"을 누르면 **Then** 관련 과정 51개가 6개씩 나뉘어 보인다.

### P03-F13 수용 기준

아래 기준은 데스크톱과 모바일에서 각각 확인한다. 고정 예시 결과뿐 아니라 현재 화면에 표시된 결과가 열기 전후 동일한지를 확인한다.

- **Given** 비교 결과가 표시된 공고 페이지에서 **When** Skillset의 "트렌드 보기"를 누르면 **Then** 동일 URL의 현재 페이지 위에 기존 트렌드 내용·출처를 담은 팝업이 보이고, 하단 버튼은 "공고 비교로 돌아가기"다.
- **Given** P03에서 트렌드 팝업을 연 상태에서 **When** X를 누르면 **Then** 팝업만 사라지고 URL·공고·비교 완료 상태·문장별 표시와 근거·결과 패널이 열기 전과 같다.
- **Given** P03에서 트렌드 팝업을 연 상태에서 **When** "공고 비교로 돌아가기"를 누르면 **Then** X와 동일하게 팝업만 닫히고 비교 결과가 유지된다.
- **Given** 팝업을 닫아 비교 결과가 남아 있는 상태에서 **When** "트렌드 보기"를 다시 누르면 **Then** 같은 팝업 하나가 열리고 비교를 다시 실행하지 않는다.
- **Given** 비교 페이지에 직접 진입해 "AI로 비교하기"로 결과를 표시한 상태에서 **When** 트렌드를 열었다가 X로 닫으면 **Then** 이전 방문 기록과 관계없이 현재 비교 결과가 남는다. 기존 결과 주소 `#result`로 진입한 경우도 동일하다.
- **Given** P02 목록에서 연 트렌드 팝업에서 **When** X 또는 "공고 목록으로 돌아가기"를 누르면 **Then** 기존처럼 목록에 남고 팝업만 닫힌다. 두 버튼을 각각 확인한다.
- **Given** P01 홈에서 연 트렌드 팝업에서 **When** X를 누르면 **Then** 기존처럼 홈에 남는다.
- **Given** P01 홈에서 연 트렌드 팝업에서 **When** "이 직무 공고 보기"를 누르면 **Then** 기존처럼 공고 목록으로 이동한다.
- **Given** 기존 트렌드 전용 주소로 진입해 목록 위 팝업이 열린 상태에서 **When** "공고 목록으로 돌아가기"를 누르면 **Then** 기존처럼 목록에 남는다.

### P03-F14 수용 기준

- **Given** 경험 요약이 있는 비교 전 화면에서 **When** 비교 패널을 확인하면 **Then** 경험 카드 안의 작은 수정 링크는 없고, 카드 아래에 "나의 이력서 수정", 그 아래에 "AI로 비교하기"가 각각 하나씩 보인다.
- **Given** 데스크톱 또는 모바일의 비교 전 패널에서 **When** 두 버튼의 크기와 배치를 확인하면 **Then** 너비는 패널 내부 가용 너비 전체로 같고, 높이는 각각 54px, 사이 간격은 8px다. 수정 버튼은 회색, AI 비교 버튼은 파란색이며 문구는 중앙에 표시된다.
- **Given** 데스크톱 비교 전 화면에서 **When** "나의 이력서 수정"을 누르면 **Then** 기존 P05 이력서 등록·수정 화면으로 이동하고 AI 비교는 실행하지 않는다. 프로토타입 확인 주소는 `/S5-resume.html`이다.
- **Given** 모바일 비교 전 화면에서 **When** "나의 이력서 수정"을 누르면 **Then** 모바일 P05 이력서 등록·수정 화면으로 이동한다. 프로토타입 확인 주소는 `/m-S5-resume.html`이다.
- **Given** 경험 요약이 긴 모바일 비교 전 화면에서 **When** 패널을 확인하면 **Then** 요약과 버튼이 겹치지 않고 "나의 이력서 수정" 문구 전체가 보인다.
- **Given** 비교 가능한 이력서가 있는 비교 전 화면에서 **When** "AI로 비교하기"를 누르면 **Then** 기존 비교 흐름이 실행되며 이력서 화면으로 이동하지 않는다.
- **Given** 이력서가 없는 상태에서 **When** 비교 페이지에 진입하면 **Then** 기존 예외 정책의 이력서 등록 안내가 보이며 이 변경을 이유로 비교 버튼을 활성화하지 않는다.
- **Given** 비교 결과가 표시된 상태에서 **When** "다시 비교"를 눌러 비교 전 패널로 돌아오면 **Then** 같은 "나의 이력서 수정" 버튼 배치가 표시된다.
