## 1. 요약

공고 원문을 그대로 보여 주고, 사용자가 저장한 이력서를 근거로 공고 문장마다 맞음, 일부, 없음을 표시한다. 오른쪽 패널에는 점수와 다음 행동 4가지를 둔다. 다음 행동을 고르면 교육, 자격증과 어학, 대외활동과 프로젝트, 지원 준비 화면으로 간다.

## 2. 왜 필요한가

- 사용자는 "내 경험이 이 공고에 맞나"를 알고 싶지만, 지금은 공고를 읽고 혼자 짐작한다.
- 1차 기획 멘토: AI가 개인에게 판단을 내려 주는 건 위험하다. 근거를 보여 주고 선택은 사용자가 해야 한다.
- 이 기능이 해커톤에서 AI를 쓰는 핵심 지점이다.
- P03-F13: 자격요건의 트렌드를 확인하려고 공고 목록으로 이동하면 보고 있던 비교 결과를 이어 읽기 어렵다. 비교 화면에서 연 트렌드는 닫은 뒤 같은 비교 결과를 계속 볼 수 있어야 한다 (2026.11.01 사용자 화면 첨부 요청 및 동작 확인).
- P03-F14: 팀 리뷰에 따라 경험 카드 밖에 찾기 쉬운 이력서 수정 보조 버튼을 두되, AI 비교보다 작은 테두리 버튼으로 구분한다 (2026.11.02 리뷰 반영).

## 3. 목표

- P03-F15: 공고를 읽을 때 담당업무·자격요건·우대사항·전형절차를 빠르게 구분하고, 비교 전후에도 같은 구획에서 내용을 이어 읽는다. 기존 구획의 가독성이 낮다는 사용자 의견과 2026.11.02 승인된 비교 전·후 시안에 근거한다.

- 공고 문장 단위로 근거를 보여 줘서, 사용자가 왜 맞음이고 왜 없음인지 이해한다.
- 비교 결과에서 다음 행동 하나를 고르게 한다.
- P03-F13: 트렌드를 확인한 뒤 재비교 없이 같은 공고와 비교 결과를 이어서 본다.
- P03-F14: 비교에 쓰일 경험을 확인한 사용자가 비교 전에 이력서 수정으로 쉽게 이동한다.

## 4. 하지 않는 것

- 합격 여부, 합격 확률, 점수 순위를 말하지 않는다.
- 이력서 문장을 새로 지어내지 않는다. 문장 다듬기는 입력한 사실의 순서만 바꾼다.
- 관심, 태도 문장 (예: "뷰티 산업에 대한 애정")은 비교하지 않고 그렇게 표시한다.
- P03-F13에서는 트렌드 데이터·순위·출처·디자인, 실제 수집 주기, AI 비교·판정 로직을 바꾸지 않는다. 기존 화면의 "실시간 공고 키워드" 명칭이 실시간 수집 구현을 뜻하지 않는다.
- P03-F13은 비교 화면 내 팝업 열기·닫기만 변경한다. 다른 진입점의 이동, 공고 목록 링크, 새로고침·브라우저 뒤로 가기의 상태 보존 방식은 변경하지 않는다.
- P03-F14에서는 이력서 입력·저장, AI 비교 로직, 수정 후 자동 복귀·자동 재비교를 새로 구현하지 않는다. 비교 결과의 문장 아래에 있는 "이력서 고치기" 링크와 P05 화면은 변경하지 않는다.

## 5. 사용자 이야기

- 취업 준비생으로서, 공고의 각 목차를 하나의 공고 카드 안에서 구분해 읽고 비교 뒤에도 같은 구획 안에서 근거를 확인하고 싶다.

- 취업 준비생으로서, 공고 원문 옆에서 내 경험과 맞는 문장을 바로 보고 싶다.
- 취업 준비생으로서, 비어 있는 요구마다 무엇을 하면 채울 수 있는지 알고 싶다.
- 취업 준비생으로서, 다음에 할 일을 내가 고르고, 그 선택을 저장하고 싶다.
- 취업 준비생으로서, 자격요건의 트렌드를 확인한 뒤 창을 닫으면 방금 보고 있던 공고와 비교 결과를 그대로 이어 보고 싶다.
- 취업 준비생으로서, 비교에 쓰는 경험을 확인하다 수정이 필요하면 눈에 잘 보이는 "나의 이력서 수정" 버튼으로 이력서 화면에 가고 싶다.

### P03-F02 사전 준비와 시연 실행 방식 (v1.8)

근거: 2026.11.02 사용자 결정 — 공고 문장 사전 구조화, LLM 일괄 호출, 영상·본선 사전 생성 결과 사용. 검수 50건 담당은 미정으로 유지한다.

- 공고 원문을 비교 전에 요구 문장 단위로 구조화해 준비한다. 사용자가 비교할 때마다 LLM으로 문장을 다시 나누지 않는다. 원문과 목차, 비교 대상 문장의 연결을 유지하고 관심·태도 제외 원칙을 따른다.
- 근거 생성은 **공고 하나의 비교 대상 요구 문장 전체와 해당 이력서를 묶어 LLM 한 번의 요청**으로 처리한다. 문장마다 별도 호출하거나 여러 공고를 무조건 한 요청에 넣는 의미가 아니다. LLM은 근거를 찾고 최종 판정은 기존 P03-F03 규칙을 따른다.
- 시연 영상과 본선에서는 위 방식으로 사전에 생성한 비교 결과를 사용한다. 시연 중 ‘AI로 비교하기’를 눌렀을 때 LLM을 새로 호출하지 않고 준비된 결과를 표시한다. 실제 서비스의 실시간 호출 운영 여부까지 결정한 것은 아니다.
- 사전 결과는 준비할 때 사용한 공고·이력서에 대응해야 한다. 변경된 이력서나 다른 공고에 기존 결과를 새 분석 결과처럼 표시하지 않는다. 시연 범위와 사전 생성 방식은 발표·시연 안내에 명시한다.
- 현재 프로토타입의 고정 문장·판정이 실제 LLM 사전 생성·검수를 마쳤다는 뜻은 아니다. 생성 도구·결과 저장·검증의 상세는 팀 리뷰 후 Spec에서 정의한다. 이번 문서 개정은 실행 방식 결정이며 구현 완료가 아니다.

### P03-F04·F05 상태 색상 개정 (v1.12)

근거: 2026.11.04 사용자가 맞음 초록·일부 기존 주황·없음 빨강 시안을 승인했다. 원문 구절의 테두리와 안쪽 배경, 결과 개수 칸 3개가 같은 상태를 같은 색으로 나타내도록 한다. 시안은 확대 색상 확인용이며 실제 배치·크기·여백은 유지한다.

| 상태 | 구절 배경 및 결과 개수 칸 배경 | 구절 글자·1px 실선 테두리 및 개수 칸 숫자·라벨 |
|---|---|---|
| 맞음 | 연한 초록 #E8F5EC | 진한 초록 #166534 |
| 일부 | 기존 연한 주황 #FFF6E5 | 기존 주황 #C26A00 |
| 없음 | 연한 빨강 #FDECEC | 진한 빨강 #B42318 |

- 원문 강조 구절은 기존 1px 실선·반경4px·줄별 박스·밑줄 없음·여백을 유지한다. 결과 개수 칸은 기존 모양을 유지하며 새로운 테두리를 추가하지 않는다.
- 대상 ‘확인하는 칸 3개’는 맞음·일부·없음의 **결과 개수 칸**을 뜻한다. 현재 데스크톱에서는 오른쪽 결과 패널, 모바일에서는 상단 결과 패널에 있으며 위치를 바꾸지 않는다.
- 데스크톱·모바일, 비교 완료·결과 직접 진입·트렌드 팝업 복귀에서 동일 색상을 사용한다. 비교 전과 다시 비교 상태에는 원문 강조를 표시하지 않는다.
- 글자와 테두리는 연한 배경보다 진하게 표시하고 상태 이름도 함께 제공한다. 긴 구절은 각 줄의 경계를 유지하며 잘림·겹침·가로 넘침 없이 표시한다. 일부는 사용자 요청에 따라 기존 색을 유지한다. 기존 일부 글자 대비3.65:1의 미결은 이번 개정으로 해결됐다고 체크하지 않는다.
- v1.13 정정: 원문 강조·결과 개수 칸뿐 아니라 **문장 아래 근거 행의 작은 맞음·일부·없음 배지**도 위 표와 같은 배경·글자색을 사용한다. 기존 배지 크기·반경·여백·테두리 없음은 유지한다. 배지를 제외했던 조건은 사용자 지적에 따라 철회한다. v1.14 정정으로 링 차트도 같은 상태 색상으로 통일한다. ‘2개’ 강조·버튼·링크 색은 유지한다.
- 문장·판정·근거·개수·비교 로직·데이터·이동은 변경하지 않는다. 빨강은 이력서에서 근거를 찾지 못했다는 표시이며 불합격 판정이 아니다. 합격·불합격 표현을 추가하지 않는다.
- 이전 F04의 파랑·회색 유지 요구와 F05 개수 칸 색상은 이번 절을 최신 기준으로 한다. 과거 구현·테스트 결과는 이력으로 유지한다.

### P03-F04 맞음·일부 테두리 추가 (v1.11 이력)

근거: 2026.11.03 사용자가 확대 이미지 시안을 승인하고 PRD·구현·테스트를 요청했다. 시안은 강조 방식 확인용이며 실제 화면의 글자 크기·배치·여백을 확대 시안처럼 바꾸지 않는다.

- 비교 완료 후 **원문 안에서 강조되는 구절**에 적용한다. 맞음은 기존 배경 `#E8F3FF`·글자 `#1B64DA`를 유지하고 `#1B64DA` 1px 실선 테두리를 추가한다. 일부는 기존 배경 `#FFF6E5`·글자 `#C26A00`를 유지하고 `#C26A00` 1px 실선 테두리를 추가한다.
- 세 상태 모두 반경4px의 박스로 구절을 감싼다. 없음은 현재 배경 `#D5DCE5`·글자 `#333D4B`·테두리 `#6B7684` 1px를 유지한다. 밑줄을 추가하지 않는다. 기존 글자 크기·굵기·구절 여백을 유지한다.
- 데스크톱·모바일 비교 완료 화면, 결과 직접 진입, 트렌드 팝업을 닫은 뒤 동일하게 적용한다. 비교 전 및 다시 비교로 돌아간 상태에는 강조 박스를 표시하지 않는다.
- 긴 구절은 줄바꿈된 각 줄에도 배경·테두리를 표시하고, 문장 겹침·잘림·가로 넘침이 없어야 한다.
- 결과 패널의 맞음·일부·없음 개수 카드와 근거 행의 상태 배지에는 새 테두리를 적용하지 않는다. 원문·판정·근거·개수·링크·버튼·목차 구획·데이터 및 AI 로직은 변경하지 않는다.
- v1.9의 ‘맞음·일부 유지’는 당시 변경 범위에 대한 기록이다. 이번 맞음·일부 테두리 요구는 이 절을 최신 기준으로 삼는다.

### P03-F04 없음 표시와 대비 (v1.9 이력)

- 없음 구절의 기존 `#D5DCE5` 배경·`#333D4B` 글자·반경4px·밑줄 없음은 유지하고, 흰 카드에서 구절 경계가 보이도록 회색 실선 테두리를 보강한다. 실제 테두리 색·두께는 Spec에서 정하고 글자 대비와 구절 식별을 각각 검증한다.

- 빈 목차 안내는 흰 배경에 `#4E5968`로 표시한다. 기본 크기의 안내·본문은 글자 대비4.5:1 이상을 수용 기준으로 삼는다.

### P03-F13 상세 동작과 영향 범위

- 진입 위치는 비교 결과의 자격요건 → Skillset → "최신 콘텐츠 트렌드와 밈(Meme)에 관심" 항목 아래 "트렌드 보기"다. 비교 전 화면에는 이 기능을 위한 새 버튼을 추가하지 않는다.
- 클릭 시 현재 비교 페이지에 팝업을 겹쳐 표시한다. 공고 목록으로 이동하거나 비교 페이지를 다시 불러오지 않으며, 현재 URL도 바꾸지 않는다.
- 팝업의 내용·순위·출처는 기존 트렌드 팝업과 같고, 비교 페이지에서만 하단 버튼을 "공고 비교로 돌아가기"로 표시한다.
- X와 하단 버튼은 모두 팝업만 닫는다. 열기 전의 공고, 비교 완료 상태, 문장별 표시·근거, 결과 패널을 유지하며 다시 비교하거나 이력서를 다시 입력하게 하지 않는다.
- P03 팝업은 Escape로도 닫는다. X·하단 버튼·Escape 모두 닫은 뒤 팝업을 연 “트렌드 보기” 버튼으로 키보드 포커스를 돌려준다. 팝업을 열면 닫기 버튼으로 포커스를 이동하고 Tab/Shift+Tab은 팝업 안에서 순환한다. 열기 버튼이 사라졌으면 비교 화면의 안전한 위치로 복귀한다. 상세 대체 위치는 Spec에서 정한다. 배경 클릭 닫기는 추가하지 않는다. 홈·목록의 기존 동작은 유지한다.

| 진입점 | X로 닫기 | 하단 행동 | 변경 여부 |
|---|---|---|---|
| P03 비교 결과의 Skillset | 동일 비교 화면·결과 유지 | "공고 비교로 돌아가기": 팝업만 닫기 | 이번 변경 |
| P02 공고 목록 | 목록 유지 | "공고 목록으로 돌아가기": 팝업만 닫기 | 기존 유지 |
| P01 홈의 키워드 전체 보기 | 홈 유지 | "이 직무 공고 보기": 공고 목록으로 이동 | 기존 유지 |
| 기존 트렌드 전용 주소 | 기존처럼 목록의 트렌드 팝업으로 연결 | 공고 목록으로 복귀 | 기존 유지 |

위 표는 데스크톱·모바일에 동일하게 적용한다. 다른 진입점의 "기존 유지"는 현재 코드의 동작 기준이다. 홈의 X까지 목록 이동으로 바꾸는 요구가 아니다. 연관 요구사항: P01-F04, P02-F07. 근거: `design/screens/10_home.py`, `20_job_search.py`, `01_base.py`, `design/scripts/export_static.py` (2026.11.01 변경 전 코드).

### P03-F14 상세 동작과 화면 구성

- 대상은 "직무 찾기 → 비교하기"로 들어온 **비교 전 패널**이다. 데스크톱에서는 오른쪽 패널, 모바일에서는 기존 비교 전 패널 위치에 적용한다.
- 표시 순서: 안내 제목 → "비교에 쓰는 내 경험" 카드 → "AI로 비교하기" → "나의 이력서 수정" → 결과 성격 안내 문구.
- 경험 카드 안의 작은 "이력서 수정 ›" 링크를 제거한다. 카드 제목과 경험 요약은 유지한다.
- 데스크톱: 두 버튼은 같은 크기 (전체 너비, 높이 52px, 반경 14px, 글자 16px·굵기 600)이고 간격은 8px다. AI 비교는 파란색 `#3182F6`, 이력서 수정은 연한 회색 `#F2F4F6` 바탕에 `#333D4B` 글자, 테두리 없음 (2026.11.02 아노 결정: 크기를 맞춰 더 깔끔하게, 강조색은 AI 비교 하나). 모바일: AI 비교 버튼은 가용 너비 전체·높이 54px를 유지한다. 이력서 수정은 보조 행동으로 높이 44px·글자 14px·굵기 600의 작은 테두리 버튼으로 표시하며 두 행동 사이 간격은 8px로 한다. 모바일에서도 터치 영역 44px 이상과 문구 줄바꿈을 보장한다.
- "나의 이력서 수정"은 흰 배경·회색 테두리와 진한 글자 `#191F28`, "AI로 비교하기"는 기존 강조색 `#3182F6`과 흰 글자를 사용한다. 주요 행동의 크기·파란색 강조는 AI 비교에 둔다 (`CLAUDE.md` 디자인 원칙).
- "나의 이력서 수정"을 누르면 기존 P05 이력서 등록·수정 화면으로 이동한다. 프로토타입 기준 데스크톱은 `/S5-resume.html`, 모바일은 `/m-S5-resume.html`이다. AI 비교를 실행하는 버튼이 아니다.

최신 리뷰 반영 배치 기준:

```text
비교에 쓰는 내 경험 카드
[          AI로 비교하기          ]  전체 너비 · 높이54px · 파랑
              간격8px
[ 나의 이력서 수정 ]                 내용 너비 · 높이44px · 흰색/회색 테두리  (모바일. 데스크톱은 [ 나의 이력서 수정 ] 전체 너비 · 52px · 연한 회색)
시연용 예시 비교 결과 안내
```

### P03-F15 공고 목차 구획 (v1.9)

- 상단 회사·공고 정보의 기존 내용은 유지한다. 네 목차는 **하나의 흰색 공고 본문 카드** 안에 담당업무 → 자격요건(Skillset) → 우대사항 → 전형절차 순서로 배치한다. 목차별 별도 배경·둥근 카드·16px 외부 간격을 제거하고 얇은 구분선과 제목으로 나눈다.
- 본문 카드 배경은 `#FFFFFF`, 페이지 배경은 `#FAFAFA`이며 그림자는 없다. 기존 비교 패널과 데스크톱 좌우·모바일 한 열 배치를 유지한다.
- 비교 전후·다시 비교·직접 진입·빈 목차·긴 문장에서 같은 구획을 유지한다. 문장 강조와 근거는 해당 목차 안에 표시하고 내용 높이에 맞게 늘어난다. 내용을 숨기거나 글자를 줄여 스크롤을 줄이지 않는다.
- 동일 공고·동일 비교 상태·동일 뷰포트에서 실제 렌더링한 본문 높이가 이번 수정 전보다 줄어야 한다. 캔버스의 `board_heights.json` 수치만 줄이는 것은 완료로 인정하지 않는다. 실제 콘텐츠가 잘리지 않는 높이로 생성물을 맞춘다.
- 원문·목차 배속·판정·개수·근거·이동을 유지한다. 새로운 접기·탭·AI 분석은 추가하지 않는다.

### P03-F02 예시 결과와 실제 사전 생성 결과 구분 (v1.9)

- 현재 고정 결과를 보여 주는 비교 전 안내와 완료 패널에는 **“시연용 예시 비교 결과”** 및 **“실제 AI 분석은 아직 연결되지 않았어요”**를 표시한다. “AI가 문장마다 근거를 찾고”라는 현재 실행을 암시하는 문구는 대체한다.
- 실제 생성 전에는 보라색 AI 배지만 단독으로 보여 주지 않고 “시연 예시”로 구분한다. 기존 “AI로 비교하기” 버튼은 목표 기능 진입 문구로 유지하되 바로 옆 안내로 예시 표시임을 명시한다.
- 실제 LLM 생성·원문 근거 검증을 완료한 조합만 후속 PR에서 “미리 만들어 둔 AI 비교 결과”로 바꿀 수 있다. 현재 v1.8의 사전 생성 정책과 Spec T36~T49는 유지하되 이번 UI 수정으로 구현 완료 처리하지 않는다.
- 검수 50건 담당은 배정하지 않고 미정으로 유지한다. 실제 결과 생성·검수 담당 배정은 후속 협의다.

## 9. 수용 기준

- **Given** 사전 구조화된 공고와 시연 이력서가 있을 때 **When** 비교 근거를 사전에 생성하면 **Then** 공고의 비교 대상 문장 전체를 한 번의 LLM 요청에 포함하고, 응답의 근거를 검증한 뒤 F03 규칙으로 판정한다. 문장별 별도 호출은 하지 않는다.
- **Given** 같은 공고·이력서 조합의 사전 결과가 있을 때 **When** 영상·본선에서 ‘AI로 비교하기’를 누르면 **Then** 공고 문장 재구조화와 새 LLM 호출 없이 해당 결과를 표시한다. 발표·시연 안내에는 사전 생성 결과 사용을 명시한다.
- **Given** 사전 결과가 없거나 입력 공고·이력서가 달라졌을 때 **When** 비교를 요청하면 **Then** 다른 입력의 결과를 대신 표시하지 않고 준비된 결과가 없음을 안내한다.

아래 기존 표시 시간 기준은 시연에서는 사전 결과 표시 시간에 적용하며, LLM 생성 소요 시간이나 실제 호출 성공을 검증한 것으로 보지 않는다.

- **Given** 이력서가 저장된 사용자가 공고 페이지에 있을 때 **When** "AI로 비교하기"를 누르면 **Then** 10초 안에 공고 문장마다 표시가 생기고 오른쪽에 "6개 중 2개가 이어져요"가 보인다.
- **Given** 비교 결과가 있을 때 **When** 없음 표시 아래 "프로젝트"를 누르면 **Then** 대외활동과 프로젝트 화면으로 간다.
- **Given** 비교 결과가 있을 때 **Then** 화면 어디에도 합격, 확률, 점수라는 말이 없다.
- **Given** AI가 이력서에 없는 문장을 근거로 돌려줄 때 **Then** 그 항목은 없음으로 표시된다.
- **Given** 교육으로 배우기 화면에서 **When** "지난 과정 포함"을 누르면 **Then** 관련 과정 51개가 6개씩 나뉘어 보인다.
