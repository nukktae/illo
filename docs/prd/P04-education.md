# P04 교육과정과 정책 PRD

버전 v1.3 검토 초안 (2026.11.01) · 담당 이민섭 · [전체 PRD](00-root.md)

**현재 작업은 조사·플로우·PRD 구체화까지다.** 이 문서는 제품 요구사항이며 구현 완료나 팀 전체 승인 상태를 뜻하지 않는다. 사용자 확정 사항과, Spec 작성을 위해 이번 검토에서 구체화한 동작 규칙을 구분한다. 공통 로그인·저장·비교 데이터 계약은 13절의 담당자 합의가 필요하다.

## 1. 확정한 제품 방향

| 항목 | 사용자 확정 내용 |
| --- | --- |
| 이용 방식 | 자유 탐색 가능. 비교 결과가 있으면 관련 교육을 먼저 제공 |
| 교육 출처 | SeSAC만 제공. 다른 공공교육·민간 강의 제외 |
| 탭 | SeSAC 교육과정 · 청년 정책 2개. 자격증·어학과 대외활동·프로젝트는 P03 담당 |
| 추천 설명 | 보완할 역량 + 관련 교육 + 연결 근거 |
| 상세 범위 | 교육은 모든 노출 과정에 공통 상세. 정책은 요약 후 공식 사이트 연결 |
| 과정 노출 | 모집 중인 과정만. 모집 예정·운영 중·종료 과정 목록 제외 |
| 정책 자격 | 조건을 안내하고 사용자가 확인. 개인별 자격 자동 판정 제외 |
| 북마크 | 로그인 후 이용. 검색·상세 확인·공식 사이트 이동은 비로그인 허용 |
| 담당 범위 | 공통 과정 상세도 이민섭 담당. P03에서 같은 상세 사용 |
| 현재 산출물 | 조사 결과·사용자 흐름·수정 PRD. Spec과 실제 개발은 이후 진행 |

온라인 ‘상시’ 13건은 현재 수집본에서 ‘모집 중’과 다른 상태다. 이번 초안에서는 자동 포함하지 않는다. 상시 과정을 포함하려면 별도 범위 변경으로 기록한다.

## 2. 문제·대상·성공 기준

### 문제와 근거

- 청년은 자신의 경험과 공고 요구를 연결하기 어렵고, 어떤 교육이 준비에 도움이 되는지 판단하기 어렵다. [기획 멘토링](../notion/회의록/2026-10-28-기획멘토링-1차.md)
- 교육·정책을 비교 흐름 밖에서도 탐색할 영역이 필요하다. [10/30 화면 구성 회의](../notion/회의록/2026-10-30-팀회의-페이지구성.md)
- 핵심은 교육 목록의 양보다 공고 요구와 교육 내용의 연결 근거다. [사용자 리서치](../notion/태스크.md)

### 대상과 사용자 이야기

주 시연 대상은 SNS 운영 경험이 있는 신입 SNS 콘텐츠 마케팅 취업준비생이다. 교육 목록 자체는 다른 분야도 탐색할 수 있다. 개인화는 P03에서 실제 비교 결과를 받은 범위만 제공한다.

- 처음 온 사용자로서, 로그인이나 이력서 등록 없이 모집 중 교육을 찾고 싶다.
- 비교를 마친 사용자로서, 내가 선택한 준비 항목과 수업 내용의 연결을 확인하고 싶다.
- 과정에 관심이 생긴 사용자로서, 일정·장소·비용·자격을 확인하고 공식 사이트로 가고 싶다.
- 정책을 찾는 사용자로서, 지원 내용과 신청 조건을 확인하고 원문으로 이동하고 싶다.
- 로그인한 사용자로서, 관심 항목을 저장하고 마이페이지에서 다시 찾고 싶다.

다음은 검증 목표이며 측정된 성과가 아니다. 5명 사용자 테스트를 기본안으로 하고 일정·진행은 팀과 맞춘다.

| 과제 | 통과 기준 | 확인 방법 |

| 추천 이해 | 5명 중 4명 이상이 어떤 공고 요구와 어떤 교육 내용이 연결되는지 설명 | 본인이 선택한 결과로 확인 |
| 저장·재방문 | 로그인 후 저장한 동일 항목을 P05에서 찾고 해제 가능 | 페이지 간 시나리오 확인 |

### 필수 범위와 작업 단계

**필수:** 2개 탭, 모집 중 교육 검색·분야 필터·정렬, 공통 상세, 근거가 있는 교육 연결, 정책 요약·필터·공식 링크, 로그인 후 북마크, 페이지 간 복귀와 실패 처리.

현재 작업의 완료물은 조사·플로우·PRD다. 제품의 Goal과 현재 문서 작업의 완료를 구분하며, Spec·실제 개발은 이후 단계에서 진행한다. 범위를 변경하면 Goal·Non-Goal·기능·수용 기준을 함께 갱신한다.

| 흐름 | 진입 | 주요 단계 | 완료·복귀 |

## 6. 목록·검색·필터·정렬 규칙

### 6.1 공통 동작

- 첫 진입은 교육 탭. `#policy`로 들어오면 정책 탭. 지원하지 않는 탭 값은 교육 탭으로 연다.
- 비교 기반 개인화 안내와 정렬은 교육 탭에만 적용한다. 정책 탭은 일반 탐색이며, 정책을 내 역량에 맞춘 추천이라고 표시하지 않는다.
- 두 탭의 검색어·필터·정렬·페이지·스크롤 상태는 분리한다. 탭을 바꿨다가 돌아오면 기존 상태를 복원한다.
- 검색은 앞뒤 공백·연속 공백·영문 대소문자 차이를 무시한다. 공백으로 나눈 검색어가 모두 검색 대상 필드 중 어딘가에 포함되는 항목을 찾는다. 오타 교정·의미 검색은 제외한다.
- 한글 입력 조합이 끝난 뒤 검색을 적용한다. 검색·필터·정렬 변경 시 해당 탭 첫 페이지로 이동한다.
- 비어 있는 검색어는 전체 검색으로 처리한다. 다른 탭의 조건은 변경하지 않는다.
- 목록 새로고침·뒤로 가기에서 검색 조건과 페이지를 복원한다. 페이지가 범위를 벗어나면 마지막 유효 페이지로 보정한다. 결과 0개면 페이지 버튼을 숨긴다.
- 조건 초기화는 해당 탭만 초기화한다. 교육의 ‘모집 중만’ 제한은 해제할 수 없다.

### 6.2 교육 목록

- 노출 여부를 판단한 뒤 검색·분야 필터·정렬·페이지 나누기 순서로 적용한다.
- 카드 필수 정보: 과정명, 캠퍼스·분야, 모집 상태·마감일, 교육 기간·시간, 저장 상태, 상세 진입.
- 사진은 선택 사항이다. 없으면 분야 색과 캠퍼스 이름을 사용한다. 태그 없음·후기 없음으로 카드를 숨기지 않는다.
- 상세 이동은 모든 카드에서 내부 공통 상세로 한다. 대표 과정 정보로 바꿔 보여주지 않는다.
- 분야는 전체·마케팅·AI·데이터·기획/PM·개발·디자인·기타 중 하나만 선택한다. 한 과정에 대표 분야 하나를 부여한다. 분류 근거가 불명확하면 기타로 둔다.
- 태그가 같다는 이유만으로 직무 연결·추천을 확정하지 않는다. 분야 분류와 역량 매핑은 별개다.
- 탭 개수는 검색 전 노출 가능 전체 과정 수, 분야 칩 개수는 검색 적용 후 각 분야 수, 목록 개수는 검색·선택 분야 적용 후 수다. 보유 데이터 210개를 현재 모집 중 개수로 표시하지 않는다.

### 6.3 교육 추천·정렬

- 유효한 비교 문맥이 없으면 기본 정렬은 마감 임박순이다. 관련 역량순은 제공하지 않는다.
- 비교 문맥은 접근 가능한 결과 참조·버전, 목표 공고, 식별 가능한 선택 역량과 공고 요구 근거가 있는지 검증한다. 같은 역량의 중복 ID는 하나로 취급한다. 알 수 없는 역량 ID나 다른 사용자의 결과를 이름 유사도로 임의 보정하지 않고 개인화를 중단한다.
- 유효한 선택 역량이 있고 연결 근거가 검수된 과정이 있으면 관련 역량순을 기본으로 한다. 관련 없는 모집 중 과정도 그 뒤에서 탐색할 수 있다.
- 관련도는 ‘사용자가 선택한 서로 다른 역량 중 해당 교육에서 근거가 확인된 역량 수’로 비교한다. 같은 역량의 근거가 여러 개여도 한 번만 센다. 적합도·합격률로 표현하지 않는다.
- 관련 역량 수 내림차순 → 모집 마감 오름차순 → 안정적인 과정 식별자 순으로 정렬한다. 마감 임박순도 같은 마감일이면 식별자 순으로 고정한다.
- 검색·분야 조건은 추천보다 우선한다. 검색 조건과 맞지 않는 과정을 추천이라는 이유로 끼워 넣지 않는다.
- 검수 자료 조회가 정상인데 연결 과정이 0개면 ‘현재 모집 중인 관련 과정이 없어요’ 안내와 일반 모집 중 목록을 제공한다. 검수 자료가 준비되지 않았거나 조회에 실패했으면 ‘관련 교육 정보를 아직 확인하지 못했어요’로 구분한다. 일반 목록에는 추천 배지·연결 근거를 붙이지 않는다.
- 관심·태도 등 P03에서 비교 제외한 요구는 교육 추천 대상으로 사용하지 않는다. 선택된 역량을 전부 지식 부족이나 실무 경험 부족으로 단정하지 않는다.

### 6.4 정책 목록·요약

- 정책명, 담당 기관, 기관 구분, 분야, 지원 내용 요약, 신청 상태·기간, 저장, 요약 펼치기, 공식 링크를 표시한다.
- 요약을 펼치면 지원 내용, 나이·거주·취업·소득·학력 등 확인된 조건, 추가·제외 조건, 신청 방법과 제출 자료를 표시한다. 값이 없으면 ‘공식 공고에서 확인’으로 표시한다.
- 정책 전용 내부 상세 페이지는 만들지 않는다. 긴 내용은 목록 안에서 접고 펼친다. 한 번에 한 정책 요약을 펼치며, 다른 정책을 펼치면 이전 요약은 접는다. 공식 원문 링크는 항상 함께 제공한다.
- 검색 대상은 정책명·기관·전체 키워드·지원 내용이다. 화면용 90자 설명이나 첫 3개 키워드에 검색을 한정하지 않는다.
- 기관 구분은 전체·서울시·중앙부처다. 이는 제공·등록 기관의 구분이며 사용자의 거주 자격을 의미하지 않는다. 대상 지역은 공식 신청 조건에서 따로 확인한다.
- 분야는 전체·취업·창업·재직자·권익보호 중 하나를 선택한다. 여러 분야에 해당하는 정책은 해당하는 모든 필터에서 검색되지만 같은 결과 목록에서 중복 표시하지 않는다.
- ‘신청 가능만’은 기본 꺼짐이다. 켜면 9절 규칙으로 확인된 신청 중·상시만 남긴다. 마감·예정·확인 필요는 제외한다. 개인의 신청 자격을 확인한 결과라는 뜻이 아니다.
- 정렬은 신청 중 → 상시 → 예정 → 확인 필요 → 마감. 신청 중은 가까운 마감, 예정은 가까운 시작, 나머지 동률은 정책 식별자 순이다. 인기도나 조회수로 개인화하지 않는다.
- 10개씩 표시한다. 탭 개수는 기본 범위의 중복 제거 정책 수, 분야별 개수는 검색·기관·신청 가능 조건 적용 후 분야별 수, 목록 개수는 모든 조건 적용 후 수다. 복수 분야의 칩 개수 합은 전체 개수와 다를 수 있다.

### 7.2 연결 근거의 최소 조건

- 추천 한 건은 선택 역량의 식별자·표시명, 목표 공고 요구 문장, 해당 과정 식별자, 공식 교육 내용의 근거, 근거 위치·URL·확인일을 가져야 한다.
- 매핑은 사람이 검수한 상태만 긍정 추천에 사용한다. AI가 초안을 만든 경우에도 검수 전에는 추천 근거로 사용하지 않는다. 원문이 이미지면 수동 확인한 내용과 이미지의 출처 위치를 남긴다.
- ‘교육에서 다룸’과 ‘사용자가 역량을 보유함’을 구분한다. 수강 후 실무 경험 충족·취업 성공을 보장하는 문구를 쓰지 않는다.
- 공고 문장과 교육 내용은 사용자가 나란히 확인할 수 있어야 한다. 표시하지 못하는 근거로 추천하지 않는다.
- P03에서 받은 사용자 입력·경험 문장은 공개 교육 데이터나 다른 사용자의 결과에 섞지 않는다. AI를 활용한 비교 결과 안내에는 공통 AI 배지를 붙인다.

### 7.3 외부 이동 규칙

- 모집 중 과정에 검증된 직접 신청 링크가 있으면 ‘신청 페이지로 가기’. 공식 상세만 있으면 ‘SeSAC에서 신청 안내 보기’로 표시한다. 외부 사이트 자체 로그인이 필요할 수 있다.
- 정책은 확인된 직접 신청 링크가 있을 때만 ‘신청 페이지로 가기’. 없으면 온통청년 또는 주관기관의 ‘공식 정책 안내 보기’로 표시한다. 정책 116건은 원본 직접 신청 주소가 비어 있어 구분이 필요하다(11절 조사 기준).
- 마감·예정·확인 필요 상태에 신청 가능 CTA를 붙이지 않는다. 공식 안내 링크는 열람 가능하다.
- 외부 링크는 새 탭으로 열고 새 탭 이동을 알린다. 돌아와도 탐색 상태를 유지한다. 외부 클릭을 신청 완료로 집계하지 않는다.
- 주소가 없거나 올바른 웹 주소가 아니면 이동 버튼을 표시하지 않고 확인 안내를 제공한다. 다른 항목 주소로 대체하지 않는다.

## 8. 로그인·저장·복귀 규칙

### 8.1 북마크

- 북마크는 과정·정책 관심 항목 저장이다. 교육 수강 신청이나 학습 진도·취업 경로 확정과 구분한다.
- 로그인 계정과 항목 종류·원본 식별자 조합으로 한 건만 저장한다. P04 목록·상세와 P05 저장함은 동일 항목을 사용한다.
- 로그인 사용자의 저장 선택은 저장 상태로, 해제 선택은 해제 상태로 끝나야 한다. 재시도나 로그인 복귀로 상태를 반대로 토글하지 않는다.
- 처리 중에는 동일 항목의 중복 요청을 막고 처리 상태를 알린다. 성공 시 관련 화면·개수를 갱신하고 ‘저장했어요’ 또는 ‘저장을 해제했어요’를 표시한다.
- 실패하면 성공 메시지를 표시하지 않고 직전 확인 상태를 유지하며 재시도를 제공한다. 응답이 유실된 뒤 재시도해도 중복 항목을 만들지 않는다.
- 마감된 기존 저장 항목은 사용자 허락 없이 삭제하지 않는다. 최신 상태로 안내하고 저장 해제 가능하게 한다. 삭제된 원본의 저장 항목도 삭제 사실을 표시하고 해제할 수 있어야 한다.
- 다른 계정으로 로그인하면 이전 계정의 저장·비교 문맥을 노출하지 않는다. 예시 저장 항목을 실제 사용자 저장함에 자동 삽입하지 않는다.
- 같은 계정으로 새로고침·페이지 이동한 뒤에도 저장을 유지한다. 여러 기기 간 동기화 보장은 공통 저장 방식 합의 전까지 표시하지 않는다.

### 8.2 비로그인·세션 만료·복귀

- 비로그인 사용자가 저장을 선택하면 대상 항목과 P04 복귀 위치·탐색 조건을 보존하고 로그인 안내를 제공한다. 안내 취소 시 현재 화면을 유지한다.
- 로그인 성공 후 원래 항목으로 돌아와 최초의 저장 요청을 한 번 처리한다. 이미 저장돼 있으면 그대로 유지한다. 자동 재개 여부는 P06과 G03 합의가 필요하다.
- 로그인 실패·취소, 만료된 복귀 정보, 유효하지 않은 대상에서는 저장을 자동 실행하지 않는다. 유효한 탐색 화면으로 돌아가 다시 선택할 수 있게 한다.
- 저장 도중 세션이 만료되면 저장 성공으로 표시하지 않고 로그인으로 안내한다. 다른 사용자의 로그인 세션에 이전 요청을 적용하지 않는다.
- 로그인 중 대상이 마감되면 복귀 후 현재 상태를 안내한다. 북마크는 가능하지만 신청 가능한 것으로 표시하지 않는다. 대상이 삭제되었으면 저장하지 않는다.
- 복귀 정보는 서비스 내부 화면과 식별자로 제한한다. 이력서 원문·사용자 경험·토큰을 주소에 싣지 않는다.

### 8.3 탐색 상태

- 보존할 상태: 진입 출처, 활성 탭, 각 탭의 검색어·필터·정렬·페이지·스크롤, 펼친 정책, 비교 결과 참조·버전과 선택 역량, 저장 대상.
- 목록 → 상세 → 목록, 목록 → 로그인 → 복귀, 탭 왕복에서 보존한다. 기기 화면 크기가 바뀌어 페이지당 수가 달라지면 보고 있던 첫 항목을 포함하는 페이지로 보정한다.
- P03의 비교·이력서 버전이 바뀌면 과거 추천을 최신 결과처럼 사용하지 않는다. ‘비교 결과가 변경되었어요’와 재진입 안내를 제공하고 일반 탐색을 유지한다.
- 비교 참조가 유효하지 않거나 접근 권한이 없으면 개인화만 중단한다. 일반 목록·상세는 계속 사용할 수 있다.

## 9. 모집 상태·기간·데이터 신뢰 규칙

### 9.1 공통

- 모든 상태 판단과 D-day는 한국시간 기준이다. 교육 기간·사업 운영 기간을 모집·신청 기간으로 대체하지 않는다.
- 공식 종료 상태는 미래 마감일보다 우선한다. 종료를 모집·신청 중으로 바꾸지 않는다. 그 외 모집 중·예정·상시 상태와 날짜가 충돌하면 확인 필요로 처리한다.
- 날짜와 시간이 있으면 공식 시각까지 적용한다. 날짜만 있으면 서비스 내부 판정은 해당 일의 끝까지 포함하되, 시각을 공식 확인한 것처럼 표시하지 않는다. 실제 시각은 공식 공고 확인 안내를 붙인다.
- 같은 한국 날짜가 마감일이면 ‘오늘 마감’, 이후는 ‘마감’. 하루 차이는 ‘D-1’. 음수 D-day를 표시하지 않는다. 열린 화면도 날짜가 바뀌거나 다시 활성화되면 재평가한다.
- 출처 URL·원본 수정일·마지막 확인일·상태 판정 근거를 구분한다. 원본 등록일을 마지막 확인일로 사용하지 않는다.
- 출처 정보가 없거나 필수 기간이 해석되지 않는 항목을 신청 가능으로 추천하지 않는다. 전체 결과를 예시 데이터로 조용히 대체하지 않는다.

### 9.2 교육 노출

목록·추천 노출에는 동일 규칙을 적용한다. 공식 ‘모집 중’ 상태, 해석 가능한 모집 시작·마감, 해당 기간 안의 현재 시각, 식별 가능한 출처가 필요하다. 공식 시간이 없을 때는 9.1의 날짜 기준을 적용한다.

| 원본·확인 상태 | 목록·추천 | 기존 주소·저장함 상세 |
| --- | --- | --- |
| 모집 중이고 기간 유효 | 노출 | 정상 상세 |
| 모집 예정·운영 중·운영 대기·종료 | 제외 | 상태 안내, 공식 정보 확인 |
| 별도 상시 상태 | 이번 범위 제외 | 공식 정보 확인 |
| 모집 중이나 마감 경과 | 제외 | 마감 안내 |
| 모집 기간 누락·해석 실패·상태 충돌 | 제외 | 확인 필요 안내 |
| 원본 삭제·비공개 | 제외 | 조회 불가 안내, 저장 해제 가능 |

### 9.3 정책 상태

온통청년 공식 코드 정의서의 신청기간 구분을 우선 적용한다. [공식 API 안내·코드 정의서](https://www.youthcenter.go.kr/cmnFooter/openapiIntro/oaiDoc)

| 신청기간 코드 | 뜻 | 처리 |
| --- | --- | --- |
| `0057001` | 특정기간 | 유효한 신청 기간으로 예정·신청 중·마감 구분. 기간 누락·해석 실패는 확인 필요 |
| `0057002` | 상시 | 공식 상시 코드로 확인. 별도 종료 공지·모순이 있으면 재확인 |
| `0057003` | 마감 | 날짜가 없더라도 마감 |
| 누락·알 수 없는 코드 | 확인 필요 | 날짜 누락을 상시로 추정하지 않음 |

여러 신청 구간이 있으면 각 구간을 보존한다. 현재 구간 안이면 신청 중, 다음 구간이 남아 있으면 예정, 모두 지났으면 마감이다. 첫 시작과 마지막 종료 사이 전체를 신청 가능으로 처리하지 않는다. 공식 마감 코드는 우선 적용하며, 그 외 코드와 구간이 충돌하면 확인 필요로 분류한다.

조건의 ‘제한 없음’도 공식 코드나 명시 문구가 있을 때만 표시한다. 빈 문자열·숫자 0·해석하지 못한 코드를 무관·제한 없음으로 바꾸지 않는다. 정책의 사업 운영 기간이 남아 있다는 사실만으로 신청 가능을 판단하지 않는다.

### 9.4 갱신·출시 전 확인

- 목록 정보는 검수된 수집본을 사용하고 사용자에게 마지막 확인일을 표시한다. 실시간 신청 현황이라고 표현하지 않는다.
- 공개·시연 직전 노출할 과정의 모집 상태·링크·핵심 조건과 추천 근거를 확인한다. 정책 상태는 원본 코드와 신청 기간으로 다시 계산한다.
- 갱신 실패 시 마지막 성공 자료와 확인일을 유지하고 갱신 지연을 안내한다. 이미 기간이 지난 항목은 오래된 상태값이 모집 중이어도 숨긴다.
- 매일 1회 확인을 운영 기본안으로 제안한다. 담당·실행 방식·정보 유효기간은 G04에서 확정한다. 만료 여부 기준이 없는 상태로 ‘검증 완료’라고 출시 승인하지 않는다.

## 10. 로딩·실패·접근성·측정

| 상황 | 사용자에게 보이는 것 | 후속 동작 |
| --- | --- | --- |
| 목록 최초 조회 | 목록 로딩 표시 | 빈 상태를 먼저 노출하지 않음 |
| 검색·필터 조회 중 | 처리 중 표시 | 최신 조건의 결과만 적용. 늦게 온 이전 결과로 덮어쓰지 않음 |
| 정상 조회 0건 | 조건에 맞는 결과 없음 | 현재 탭 조건 초기화. 교육 노출 제한은 유지 |
| 전체 모집 중 교육 0건 | 현재 모집 중인 과정 없음 | 정책 탭·공식 SeSAC 안내 링크 |
| 목록 조회 실패 | 불러오지 못했어요·재시도 | 실패를 0건으로 표시하지 않음. 이전 결과는 이전 자료임을 표시 |
| 상세 조회 실패 | 상세 재시도·목록 복귀 | 다른 대표 과정으로 대체하지 않음 |
| 정책 요약 실패 | 해당 항목의 재시도·공식 링크 | 다른 목록은 사용 가능 |
| 개인화 참조·매핑 실패 | 추천을 확인하지 못했어요 | 일반 탐색 유지, 비교 결과 복귀 |
| 저장 처리 중·실패 | 처리 중·실패 메시지 | 직전 상태 유지, 재시도. 다른 탐색은 가능 |

- 무한 로딩을 허용하지 않는다. 조회·저장의 대기 한도 기본안은 10초이며 공통 Spec에서 환경별 한도를 확정한다. 한도 초과 시 실패·재시도를 제공한다. 특히 저장은 요청 취소만으로 실패가 확정되는 것이 아니므로, 늦은 성공 응답과 재시도에서 최종 저장 상태를 다시 확인한다.
- 키보드로 탭·필터·목록·요약 펼치기·저장·외부 링크에 접근 가능해야 한다. 포커스 표시와 상태별 텍스트를 제공한다.
- 선택·저장 상태를 색만으로 구분하지 않는다. 북마크는 항목명과 저장/해제 상태를 읽을 수 있어야 한다. 결과 개수·처리 완료·오류를 보조기술에 알린다.
- 입력 글자는 16px 이상, 주요 누름 영역은 44px 이상을 기준으로 한다. 모바일에서 탭·필터·본문·하단 행동이 가려지거나 페이지 전체가 가로로 밀리지 않아야 한다.
- 개인화 여부와 무관하게 교육·정책 신청 자격은 사용자가 확인한다. 내부 개발 정보나 코드값을 사용자 화면의 설명으로 노출하지 않는다.
- 검증 시 기록할 행동: 목록 진입, 필터·검색 결과, 과정 상세 확인, 근거 확인, 저장 성공·실패, 공식 링크 클릭. 수동 관찰로도 측정 가능하며 분석 서비스 도입은 이번 범위가 아니다.
- 비교·교육·정책 식별자와 결과 유형만 측정에 사용한다. 검색 원문·이력서·경험 문장·인적사항은 행동 로그에 기록하지 않는다. 공식 링크 클릭과 실제 신청은 분리한다.

### 11.3 데이터 준비 완료 조건

- 노출할 모든 과정의 필수 식별·출처·모집 기간·상태를 확인한다. 누락 과정은 임의 채움 대신 노출 보류하고 누락 목록으로 남긴다.
- 모든 노출 과정에 공통 상세를 연결한다. 동일 이름의 다른 기수·캠퍼스를 하나의 과정으로 합치지 않는다.
- 추천으로 보여줄 모든 역량·과정 연결에 교육 근거와 검수 상태가 있어야 한다. 일반 탐색 데이터와 추천 검수 데이터의 범위를 구분한다.
- 정책 코드·복수 분야·조건·원문이 변환 과정에서 유실되지 않아야 한다. 공식 링크와 직접 신청 링크를 구분한다.
- 원본 수정·폐강·모집 종료가 반영돼도 항목 식별자를 유지하고 이전 저장 기록과 연결한다. 저장 기록 유지를 위해 종료된 원본을 무조건 물리 삭제하지 않는다.
- 신규 수집본 검증 실패 시 이전 정상 자료를 깨뜨리지 않는다. 검증 결과·실패 사유·기준일을 확인 가능하게 한다.
