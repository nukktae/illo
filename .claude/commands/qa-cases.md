description: 기능의 수용 기준으로 테스트 케이스를 만들고 빠진 테스트를 찾는다 (예: /qa-cases P03-F02)
argument-hint: P03-F02 또는 P03
---

$ARGUMENTS 의 테스트 케이스를 정리한다. 한국어로 답한다.

1. 읽기: 해당 PRD의 기능 요구사항, 예외와 빈 상태, 수용 기준. Spec의 테스트 표. 이미 있는 테스트 코드.
2. Given, When, Then 표로 만든다. 열: ID, Given, When, Then, 종류 (정상, 실패, 예외), 자동/수동, 이미 있음/없음.
3. 프론트 화면 확인처럼 자동화가 어려운 것은 "수동" 으로 두고, 미리보기 링크에서 누를 순서를 적는다.
4. 빠진 테스트를 위에서부터 중요한 순서로. 내가 OK하면 자동 테스트 코드를 추가한다.
5. 버그를 고친 뒤라면, 그 버그를 다시 잡는 테스트와 이전 기능이 안 깨졌는지 보는 테스트를 꼭 넣는다.
