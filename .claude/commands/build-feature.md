기능 $ARGUMENTS 하나만 만든다. 다른 기능은 건드리지 않는다.

1. 읽기: `CLAUDE.md`, 이 기능이 있는 PRD와 Spec, Spec에 나온 기존 코드. 프로토타입 화면이 있으면 해당 `design/screens/` 파일로 디자인을 확인한다.
2. **먼저 계획만**: 바꿀 파일, 만들 함수와 API, 테스트 목록, 모르는 점. 내가 OK하기 전에는 코드를 쓰지 않는다.
3. OK 뒤: 테스트를 먼저 쓰고 실패하는 걸 확인한 다음 코드를 쓴다. 테스트를 실행해 결과를 그대로 보여 준다.
4. Spec이나 PRD와 다르게 해야 할 이유가 생기면 멈추고 묻는다. 문서를 바꿔야 하면 바꿀 문장을 제안한다.
5. 끝나면: 바꾼 파일 목록, 테스트 결과, 미리보기에서 사람이 눌러 볼 수용 기준, 커밋 메시지 제안 (`$ARGUMENTS 무엇을 왜`).
6. 키, 개인정보, `prototype/` 직접 수정은 하지 않는다.
